## Git transfer accounting — Polaris decision

The injected real `ObjectStoreTransport` is confined to a disposable temporary clone with an origin from the preregistered public HTTPS repository list. It measures the size of `.git/objects` (packs included **once**) before and after each fetch and takes the conservative **maximum** of growth and usable C-locale progress-byte reports. It does not add duplicate estimates. Failed but measurable fetches still consume bytes. A shrinking/unreadable object store, timeout or other unmeasurable transfer stops the cohort as **acquisition incomplete at ceiling**. An over-budget measured transfer also stops it and no next fetch is issued. The cumulative budget remains 2 GiB.

This is the authorized **object-store-growth proxy**, not a wire-byte guarantee. A single fetch can cross the remaining allowance before its final size is known; retain that observed overage and stop, rather than claim it never happened. Fetch receipts/tests cover byte accounting, unmeasurable sizes, stale heads, failed fetches and refusal of the next fetch. The real transport was tested only through injected fake subprocesses; no real `git fetch` was executed, even against a local remote.

D-R2a: GET transport has at most three attempts, a 60-second timeout and deterministic 1/2-second exponential backoff between attempts. Timeouts, connection errors (including partial-transfer failures) and HTTP 5xx qualify; credential/configuration failures, malformed success output and ordinary 4xx do not. Every attempt has an exclusive fsynced request claim and separate result: exit status (null if unavailable after timeout), HTTP status, safe response headers, exception kind, sanitized stderr, timestamps, wait and outcome. All attempts count against the unchanged endpoint-class and global budgets; cache hits do not. Tokens, authorization headers, URL credentials and local account/cache prefixes are removed from stderr. A missing durable response after process interruption is never silently retried on restart; only the bounded live operation may retry.

Polaris's rate-limit clarification is pinned: retry HTTP 429, or HTTP 403 carrying Retry-After or x-ratelimit-remaining: 0. Every other 4xx, including plain 403/404/410/422, is final and repository-local. Wait Retry-After (seconds or HTTP date), otherwise until x-ratelimit-reset. A wait at most 300 seconds is honored; a larger or unknowable required wait stops the cohort as `acquisition-incomplete-rate-limited`, without waiting or changing credentials. No fourth attempt occurs. The final rate-limited attempt still honors a permitted cooldown before moving to another repository. The global stop survives a client restart. A server Retry-After on retryable 5xx is honored under the same wait ceiling. Existing metered fail-closed Git transport is unchanged; an unmeasurable transfer still stops the cohort, and no unmeasured Git retry is introduced.

D-R2b: ordinary repository acquisition errors preserve its selected prefix, mark it acquisition-incomplete and continue the next repository. Only global request/transfer exhaustion or the global rate-limit stop halts the cohort; per-repository or sub-budget exhaustion remains local. Invalid apparatus/authorization/runtime integrity still fails closed before transport. Overall completeness remains false even when other repositories succeed.

D-R2c: only an integrated-earlier-pr contamination shape can use the pre-update fallback. Find the oldest first-parent crossing into the earlier integration's ancestry; it must be a two-parent merge whose side parent is on pinned default first-parent history. All side-parent ingresses of the integration or earlier PR head must be from that default history; direct/stacked PR ingress is not hidden by a rewind. The sole candidate is the first parent immediately before that merge, and it must appear in the complete pinned PR commit list. Recompute own bases and rerun every unchanged B2 test; failure excludes the pair, without trying earlier candidates. Preserve final/effective heads and both proofs, bind the candidate locally, record `head_kind = final-head` or `pre-update`, and report the two strata separately. This is graph-only and outcome-blind; no oracle or detector selects a head.

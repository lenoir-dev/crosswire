# S17b implementation — synthetic-only review stage

This implements revision 3 plus accepted Vega re-review R1–R5 of `docs/design/s17b-concurrent-pr.md`, including Polaris's clarified **20 metadata-passing pairs** cap. Metadata failures retain rank/outcome and consume no slot; every post-metadata failure keeps its slot with no replacement. This package has collected **no actual GitHub metadata**, executed **no actual fetch**, and labelled **no real PR pair**. Tests construct local Git graphs or inject fake pages/receipts.

The policy now contains the reviewed-cutoff/API/installed-gh/runtime pin proposal; it is **not authorization or checkpoint 1**. Its ready status only allows an explicitly requested offline checkpoint. After Vega checks the acquisition wiring and Polaris authorizes checkpoint creation, refresh detector_commit to the actual HEAD at checkpoint creation and write the first durable checkpoint **before any API call**. Do not substitute repositories, bounds, seed or ceilings after that checkpoint. The offline checkpoint mode is:

```sh
python -m benchmarks.s17b --policy "$S17B_POLICY" --write-checkpoint "$S17B_CHECKPOINT"
```

It performs no acquisition. A missing ready status or mismatched runtime still fails readiness checks; populated pins do not authorize collection. The checkpoint exclusively creates a mode-0600 file, fsyncs content and directory, embeds the exact configured policy and its canonical SHA-256, and hashes code/tests/design/M3/shared Git helpers. `Permit` then requires a separate explicit Polaris authorization record bound to that checkpoint hash and revalidates code before network transport. This is a procedural guard, not a cryptographic authority or an OS sandbox. No real authorization record was created by this task.

## Code boundaries

- `selection.py`: strict UTC intervals, list-only possible overlap, canonical seeded pair hashes, lazy cached metadata filters, all evaluated ranks/outcomes, incomplete-prefix handling and PR-reuse counts. Metadata order is A-detail → A-timeline → A-files → B-detail → B-timeline → B-files, short-circuiting at the first failure and recording its PR/stage/filter. Terminal chronology must be evidenced by the complete timeline; missing/inconsistent evidence is a metadata failure, never an invented open episode. Drafts at close qualify. Python rename/file-list completeness is checked without looking at labels or CI.
- `acquire.py`: injected read-only GET client, explicit `gh api --method GET`, gh/API version pins, cached response/header provenance, exclusive request claims and a cumulative GET budget across client restarts. A started request with no durable response cannot be silently retried. Closed listing samples at least one further full page after the old-updated boundary, records final Link/page counts and tail violations, and continues to exhaustion on a violation. It discloses currently-open reopened PRs as a coverage hole.
- `collect.py`: bounded orchestration in fixed repository order, public repository/default-branch/default-SHA metadata pinning, no labels/Git/oracle. Default SHA lookup adds a read-only `GET repos/<owner>/<repo>/commits/<encoded default branch>` request, charged to the same 1,500-GET ceiling. Each repository has a fixed non-rolling 187-GET all-inclusive budget (1,496 total; four requests unallocated and unusable). Repository exhaustion continues the next allocation; a global ceiling marks the remaining cohort unattempted. No partial universe is claimed complete.
- `graph.py`: local Git-only B1 true-merge/n=1/proven-rebase/proven-squash anchors with `anchor_method`; no message conventions. Squash needs complete negative key/patch matches plus all-plus cherry for exactly the non-merge PR commits, and a complete rename-aware changed-path set match. Proven rebase uses a whole ordered author/date/subject or patch-id sequence. B2 rejects C/earlier-head containment, shared PR-only ancestry and intersecting patch-id sets **before integration**. Empty/root/merge/unavailable patches fail proof rather than becoming empty independence sets.
- `pipeline.py`: selected-slot acquisition and anchor/base/contamination records, no replacement, ceiling tail, optional native virtual states with reverse-tree equality and reachable local evidence refs. `m3_contract` uses unchanged frozen M3 for both own-base and common-later-base checks; attribution uses I_AB only. It takes supplied observations and does not execute any oracle.
- `checkpoint.py`: offline readiness/hash record and explicit future authorization gate. The measured detector and full runtime/oracle freeze belong to the later checkpoint 2, before labels; they are not fabricated here.

## Git transfer accounting — Polaris decision

The injected real `ObjectStoreTransport` is confined to a disposable temporary clone with an origin from the preregistered public HTTPS repository list. It measures the size of `.git/objects` (packs included **once**) before and after each fetch and takes the conservative **maximum** of growth and usable C-locale progress-byte reports. It does not add duplicate estimates. Failed but measurable fetches still consume bytes. A shrinking/unreadable object store, timeout or other unmeasurable transfer stops the cohort as **acquisition incomplete at ceiling**. An over-budget measured transfer also stops it and no next fetch is issued. The cumulative budget remains 2 GiB.

This is the authorized **object-store-growth proxy**, not a wire-byte guarantee. A single fetch can cross the remaining allowance before its final size is known; retain that observed overage and stop, rather than claim it never happened. Fetch receipts/tests cover byte accounting, unmeasurable sizes, stale heads, failed fetches and refusal of the next fetch. The real transport was tested only through injected fake subprocesses; no real `git fetch` was executed, even against a local remote.

## Accepted implementation-review fixes, before checkpoint 1

C1 records required-event proximity to both the field and last terminal timestamp (≤policy tolerance, 60 seconds), signed field skew and last-terminal gap; the first ten distinct merged PRs with complete detail/timeline form the outcome-blind health sample. All ten failed proofs stop that repository acquisition-incomplete; file retrieval still short-circuits after timeline failure. C2's path allowlist comes from policy repository membership and only detail/pulls/issues/commits resources; no rate_limit or usable headroom endpoint remains. C3 `prepare_clone` is itself permission-gated: fresh local init, fixed public origin, metered full default-history fetch and strict pinned-SHA comparison. Every actual fetch disables gc.auto and maintenance.auto. Initial/default/PR transfers share one policy-derived cohort budget; no real fetch is exercised by tests.

M1 discards only provably out-of-window list PRs before ranking. m1 default-chain empty/root/merge patches are non-matches, not failed squash evidence. m2 deliberately retains conservative merge-containing PR patch-set exclusions: those PRs may anchor then become contamination-proof-unavailable, reducing yield; this must be counted/disclosed. m3 removes the dead source_base parameter. m4 caches head outcomes without repeating transfers. m5 keeps the highest-updated duplicate list snapshot, logs both hashes and fails contradictory terminal data. m6 requires ready status and exact Python/Git pins (Git≥2.38), checked again by Permit; the measurement-time ceiling stays a checkpoint-2 obligation. m7 distinguishes merge-tree operational failures from textual conflict. See the design for the complete dispositions.


## Checkpoint-1 acquisition entry

```sh
python -m benchmarks.s17b --acquire --checkpoint ~/.crosswire-evidence/s17b/checkpoint-1.json --authorization ~/.crosswire-evidence/s17b/authorization.json --root "$S17B_ROOT"
```

`S17B_ROOT` must be a fresh directory beneath the system temporary directory. No acquisition runs without Permit verification; the command never creates its checkpoint or authorization. Metadata selection is exclusively written/fsynced before any initial default-history fetch. It then acquires the selected graph/heads with the already reviewed graph rules, without virtual integration, oracle/detector execution, labels or checkpoint (2). Missing/stale/default failures retain selected slots; all default/head transfers share one policy-sized budget. A measurable overage stops the next fetch. Private local evidence contains started/metadata/per-repository/final acquisition JSON and the API cache. Existing roots are rejected: there is no automatic replay/resume. Interrupted evidence remains as-is for audit. Exit 1 means acquisition incomplete; exit 0 means acquired graph evidence, never a measurement verdict.

The command takes policy only from the verified checkpoint, never from an extra policy argument. `--write-checkpoint ... --policy ...` stays a separate offline mode. Permission files are procedural same-user guards, not signatures. This entry is step (1)+(2) review work only; the checkpoint file and actual authorization still await Vega/Polaris. See `docs/validation/s17b-cp1-resume.md` for the pending sequence, detector HEAD pin and exact authorization fields.

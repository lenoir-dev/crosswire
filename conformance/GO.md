# Go conformance renderer — S19

Run the Go oracle/template kit with an installed **Go 1.27.1**:

```sh
python -m conformance.go_run --output /tmp/crosswire-go-conformance
```

`--go` selects the pinned executable; `--case` selects explicit IDs and records a partial run. Output must be fresh. **Detector: not available** until T25. A zero exit means only that the declared templates and oracle agree; every case and summary explicitly retains the unavailable detector status, with zero detector mode checks. It is never a Go detector pass. Oracle/template disagreement, a wrong toolchain, incomplete coverage, unexpected diagnostic category/location, timeout or source/toolchain drift is a kit bug (exit 2).

The ten Go counterparts of the shared S16 scenarios cover GO-1 rename/delete/third-branch repair, GO-2 package movement and GO-3 argument-count change, each with its existing control. Conjunctive removal and both open-namespace templates (six cases including controls) explicitly report **no Go counterpart**; they are not passing Go cases. Existing Python templates, renderer, runner and their frozen hashes are unchanged.

`render/go.py` maps logical modules to package directories in the fixed dependency-free module `example.invalid/crosswire/conformance` (`go 1.27.1`). Logical exported names become Go identifiers, directory movement retains the package clause, and consumers import a fixed explicit alias. A Python-compatible optional trailing parameter becomes a Go variadic parameter. Third-branch forwarding replaces the same direct declaration with an exported function alias: Go cannot shadow a declaration with an import. Each target/tip/subset is built independently from native textually clean merges. Stable independent edit slots make same-file declaration additions and duplicate imports survive clean textual integration. Repeated rendering and Git commit IDs are deterministic.

`templates/go/redeclaration.json` adds eighteen language-neutral GO-4 cases: same-file and cross-file declarations; identical declarations; function/type/var/const namespaces; receiver method `T.Name`; duplicate per-file import aliases; distinct-name controls; and repeated `_` / `init` exemptions. Python has no equivalent error contract for these cases (CW003 remains a separately reported Python warning). Declaration-pair identity is explicit in each template, and raw compiler/checker locations are retained. Package names intentionally differ from directory names for the two imported packages.

The semantic command is exactly `GOFLAGS=-mod=readonly go build -gcflags=-e ./...`, with `GOTOOLCHAIN=local`, `GOENV=off`, `GOWORK=off`, `CGO_ENABLED=0`, fixed **GOOS=darwin / GOARCH=arm64**, no custom tags, and isolated fixed GOCACHE/GOMODCACHE/GOPATH for the run. All fixtures contain production sources only, no external dependencies or downloads; GOPROXY/GOSUMDB are off and GOVCS denies retrieval. No test code, vendor directory, workspace or replacement directive enters a proof. `go vet` is not run and cannot affect labels.

`go_categories.go` is a byte-identical copy of S19a's helper, shipped with the kit rather than requiring the benchmark directory in an sdist. The pinned helper reads `go list -e -deps -export -json ./...`, uses `go/types`, and records code plus source position; the code-name table comes from the pinned toolchain. Compiler positions must match helper positions/spans. English messages are audit evidence only. A first-party BrokenImport is GO-2 only for an absent generated package, and validation must also match the declared use/package. Duplicate imports are GO-4, superseding the historical census mapper's GO-7 mapping without changing that old apparatus. Duplicate-import masking can additionally emit UnusedImport at one of those same import sites; the template declares that dependent category explicitly, and it is not counted as a second root cause or GO-7 observation. Other unexpected/multi-root diagnostics fail closed.

The small helper executable is compiled for the recorded host so it can run; semantic source builds and go/types Sizes use the fixed target above. Provenance hashes the Go binary, compiler, pinned code table, helper source/binary, and all kit files. Each rendered case records exact sources/edits and expectations beside independent per-subset oracle verdicts, diagnostics and source hashes. Go build/list/helper execution must leave all source/module files and protected Git state unchanged. This is a synthetic contract kit, not a natural Go corpus or a precision/recall measurement.

Tests: `pytest -q tests/test_conformance_go.py`. Pure renderer/protocol tests run without Go. Compiler checks skip locally when Go is absent; `CROSSWIRE_REQUIRE_GO=1` makes absence a failure. CI installs Go **1.27.1** on Ubuntu and macOS with `check-latest: false` and setup-go caching disabled, and sets this requirement for every Python matrix job. An installed wrong version also fails.

The required-Go test run uses eight explicit cases / 32 oracle states: rename, package move, conflicting and compatible arity changes, same-file and cross-file redeclarations, duplicate methods and duplicate import names. It records a **partial** selection and zero detector mode checks. All renderer/protocol tests still run. Reproduce CI with `CROSSWIRE_REQUIRE_GO=1 pytest -q tests/test_conformance_go.py`; the full 34-case / 120-state kit remains the separate `python -m conformance.go_run --output NEW_DIR` command (and the default local test with Go installed). Detector comparisons still await T25.

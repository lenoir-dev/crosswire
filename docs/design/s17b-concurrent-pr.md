## Selection, before builds

Cohort: the eight public repositories below; **both PRs’ terminal events must be on or after `2022-01-01T00:00:00Z` and strictly before `collection_cutoff`**. Pin that lower bound and one exact UTC `collection_cutoff` **no later than collection start** in the accepted selector policy before requesting metadata; the cutoff does not advance during collection. There is no creation-date restriction: a PR opened before 2022 can qualify if its terminal event is in the fixed window. Include merged and closed-unmerged PRs and drafts, including PRs still draft at close; do not filter on CI, mergeability, review, title, conflict-related words, checker results or eventual success. Require the same target repository and its pinned default-branch name in both PRs. Base consistency and lifecycle completeness are lazy metadata filters. Redirected/reopened/uncertain PRs fail those filters, retain their rank/reason in the evaluated ledger, and consume no cohort slot; do not represent reopening as one continuous interval.

For an unreopened terminal PR `i`, define `open_i = [created_at, end_i)`, with `end_i = merged_at` when non-null, otherwise `closed_at`. Validate `created_at < end_i`, terminal-state consistency and `merged_at <= closed_at` when both exist. Pair `A.number < B.number`; overlap means **`max(created_A, created_B) < min(end_A, end_B)`**. Equality is not overlap. A still-open PR at the fixed cutoff, missing/inconsistent timestamps or an unresolvable default-branch rename is not a member of this terminal-PR cohort; record that metadata-filter outcome at its evaluated rank without consuming a slot. A reopened PR is not represented by its outer interval; reject it at metadata validation rather than infer missing episodes.

Both PRs must touch at least one `.py` path (current or previous filename on a rename), based on complete paginated PR-file metadata. File overlap is **not required**: a producer and consumer can change different files. Record shared-file/shared-module flags for later descriptions, never ranking. If Python-touching cannot be established from a truncated file list, record a metadata-uncertain filter failure at that rank without consuming a slot; do not assume it is non-Python or send it to the oracle. The PR-files endpoint caps responses at 3,000 files, so compare retrieved count against the PR detail's `changed_files`; no incomplete list is trusted. [GitHub PR-files contract](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests-files).

**N1 ordering and cap (Polaris clarification):** enumerate possible overlap using **list data only**, then sort by **SHA-256 of `"s17b-v1|<repo-id>|<A>|<B>"` ascending**. Only list-derived possible overlap and provable terminal-window failure are pre-ordering; no detail/files/timeline calls precede ranking. Keep malformed/missing list timestamps in an explicit uncertainty ledger; where overlap cannot be ruled out, rank the pair as a possible candidate and reject at lazy metadata validation. A provably non-overlapping pair or a PR with a provably out-of-window terminal field never enters the order; record list-level exclusion counts. Uncertain/malformed timestamps stay ranked. Walk the hash order lazily, caching PR-level responses, with **fixed short-circuit order**: list-only possible overlap; **A detail → A timeline → A files → B detail → B timeline → B files**. Detail checks terminal consistency/window/default base/changed-file count; timeline checks lifecycle/reopen/base history; files check complete Python-touch. Record the first failed filter **and PR label A/B**; never request the later stage or B after A fails. Continue in hash order until **20 METADATA-PASSING pairs per repository** (≤160 total), the order is exhausted, or a ceiling stops collection. For every evaluated pair record its hash, rank, metadata outcome and failed filter, even when rejected. Metadata failures do **not** consume a cohort slot. Once a pair passes metadata and receives a cohort slot, **every later exclusion consumes that slot with no replacement**, including unavailable heads and unproven anchors. This equals eager “filter all metadata, then take the first 20 by hash”, but bounds GETs by a deterministic evaluated prefix. Never replace a post-metadata exclusion to reach 20 successful builds.

Record `pair_order_seed = "s17b-v1"` and this encoding contract in policy before collection: `<repo-id>` is the stable numeric GitHub repository ID; PR numbers satisfy `A < B`; all are canonical unsigned decimal without leading zeros; UTF-8 bytes, literal `|` separators, no quotes or newline. Sort digest bytes (equivalently lowercase hexadecimal), breaking a digest collision by numeric `(A,B)`. The seed is public and fixed; changing it requires a **new preregistration**, not a retry. ## Immutable heads and default-branch context

Use disposable public clones outside the project worktree. Pin default-branch history once; perform no checkout, ref update or commit in crosswire itself. Fetch each selected unique PR with **`git fetch --no-tags origin refs/pull/<n>/head`**, immediately resolve `FETCH_HEAD^{commit}`, and save the object under a dedicated local evidence ref in that disposable clone. Never fetch `refs/pull/<n>/merge` as ground truth. Compare the fetched SHA with the pinned PR detail's `head.sha`; ref absence, permission/transport failure or a changed SHA is **unlabelled**, with no replacement or silently updated selection. A deleted fork must not trigger a fetch from an arbitrary supplied fork URL. Preserve an object bundle for audit if GitHub later removes a head. [GitHub's PR-head retrieval instructions](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/checking-out-pull-requests-locally).

Final heads are mandated by P3 but can contain work authored **after the overlap**. Record the overlap endpoints and each head's authored/committed times; never claim these trees actually coexisted. Commit times cannot reconstruct force-push histories. This stratum asks about final natural branches associated with concurrent PRs, under a virtual integration. Historical CI success is metadata, not oracle ground truth, and is never a selection requirement.

**Strict default snapshot rule (confirmed by Polaris):** using today's default HEAD can make a merged PR head its own merge-base and erase its change. For pair cutoff `c = min(end_A, end_B)`, reconstruct a default snapshot `D` before the earlier terminal event. The authoritative anchor is that earlier PR's API `merge_commit_sha`, verified on the pinned default first-parent chain. For terminal-time ties: **if exactly one PR is merged, it is E**; if both are merged, their order on the pinned default first-parent chain chooses E; identical C values, missing chain proof or neither merged is unresolved. No timestamps or message conventions break a graph ambiguity.

Let `C = merge_commit_sha` of the earlier-ending PR, and `n` its pinned detail's commit count. Require the PR to be merged and `C` on the pinned default first-parent chain. Its complete PR-commit list and corresponding Git objects must be available; count/truncation mismatches are unresolved. No commit-message conventions (`(#N)`, “squash” etc.) are evidence. **Compare oldest-to-newest**: retain the pinned PR API commit list’s oldest-first sequence and validate it against the graph; reverse the newest-first default `rev-list` output before comparison. A reversed PR sequence must not match. Compare this ordered full PR list with the inclusive last `n` first-parent commits `[C~(n-1), ..., C]` (retrieve with `rev-list --first-parent --max-count=n C`; do not accidentally omit the oldest commit with a half-open range).

- **True merge commit:** verify `C` and its parent/head relation in the graph; **`D = first parent`**, `anchor_method = merge`.
- **Single-parent `C`, `n == 1`:** squash/rebase distinction is unnecessary; **`D = C^`** with no merge-method evidence. Use audit enum `anchor_method = squash-n1` as the accepted **method-neutral n=1 rule**, not a claim that GitHub used squash.
- **`n ≥ 2`, rebase proven:** the last `n` single-parent first-parent commits ending at `C` match the complete PR list **one-to-one, in order**, either by **(author name/email, author date, subject)** or by **`git patch-id --stable`**. Require the entire tuple sequence or entire patch-id sequence, not a mixture of partial matches. Then **`D = C~n`**, `anchor_method = rebase-proven`; conflict-resolved rebases can qualify by preserved full metadata even if a patch-id changes. Record which proof fired and its input hashes. Empty/unrecoverable patch IDs cannot prove a patch-id sequence; the full metadata proof can still qualify.
- **`n ≥ 2`, squash proven:** `C` is single-parent, **no** commit in that inclusive last-`n` chain matches **any** PR commit by either full tuple or stable patch-id, and **`git cherry C H_E B_PR` reports `+` for every non-merge PR commit, with exactly that non-merge count of output lines** (Git cherry omits merges), where `H_E` is the earlier PR head and `B_PR` is its source-range boundary. Verify `B_PR..H_E` exactly equals the complete pinned PR-commit set before using this command; unavailable/nonlinear range evidence is unresolved. PR merge commits are covered by the negative full-tuple test, not fabricated patch IDs or cherry output. Also require the set of paths changed by **`C^..C` (including old and new rename paths) to equal the complete PR-files path set**; a mismatch is unresolved, preventing a rewritten multi-commit rebase tail from posing as a squash. Then **`D = C^`**, `anchor_method = squash-proven`. **Do not require its tree to equal a virtual application of the PR diff.** Record the negative-match and cherry evidence; a plausible subject is not proof.
- **Anything else**, including partial matches, insufficient objects/range evidence or closed-unmerged PRs: **`default-anchor-unresolved`**, `anchor_method = unresolved`. **Chosen R5 policy:** an earlier closed-unmerged PR stays in the metadata cohort and consumes its slot as unresolved (it is not a non-consuming metadata filter). A closed-unmerged PR's API `merge_commit_sha` can name a test merge and is **never an authoritative anchor**. An unresolved slot is consumed, not replaced.

Record `anchor_method` per selected pair (including unresolved), along with `C`, `n`, `D` where known and proof digests. A copied subject alone neither proves rebase nor forbids squash; full keys/patches and the complete sequence decide. This adopts B1 item 3: proven multi-commit rebases are accepted, not blanket-excluded.

There is **no timestamp-proxy cohort in this round**, and no replacement pair for an unresolved anchor. Timestamp overlap remains a selection criterion, not proof of default-branch ancestry.

Compute **each own base** `B_i = unique merge-base(H_i, D)` from pinned objects; missing/multiple bases or `B_i == H_i` are unlabelled (already contained or ambiguous). Record both bases and the default anchor. Require the bases to be ancestry-comparable: if `B_A` is ancestor of `B_B`, later base `L = B_B`, and conversely; equality is allowed. **Later means ancestry, not author/committer date.** On a linear default first-parent history the bases are ancestry-comparable; incomparable bases are primarily a merge-heavy-history issue and remain unlabelled. Never invent a new merge baseline.

**B2 contamination, before ANY virtual integration or checker run:** let `E` be the earlier-ending PR and `F` the other (canonical numeric A/B order is not terminal-time order). Require all three graph/patch checks:

1. **Neither `C` nor `H_E` is an ancestor of `H_F`** (`merge-base --is-ancestor`); also reject identical heads or either head ancestral to the other. This catches a later PR updated from default after E's merge, including rebase/squash integrations where `C` differs from `H_E`.
2. **`merge-base(H_A,H_B)` must lie in default ancestry of `D`**, verified by ancestry, not timestamps. A shared PR-only prefix/stacked branch outside D fails; multiple/unavailable merge bases are unlabelled. Record the corresponding non-default-history intersection evidence.
3. The stable **patch-id sets of `B_A..H_A` and `B_B..H_B` must be disjoint**. Nonempty intersection → `contaminated-heads`, unlabelled. Pin exact patch extraction/empty/merge handling before freeze; inability to establish required patch identity is unlabelled, not an empty set that falsely proves independence.

These tests use graph/patch-id evidence only, never checker output or commit-message conventions. Record the failed test and counts per repository; every failure consumes its selected slot. Required negative: unrelated heads with **similar-looking changes but different computed stable patch IDs** pass. **Concrete limitation:** independently authored identical normalized patches have equal patch IDs and are intentionally excluded under B2; origin cannot be distinguished from cherry-picking by this evidence. Do not write a negative test that demands accepting identical patch IDs.

## Integration and exact M3 reuse

Construct states using pinned native Git merges, never textual patch concatenation or conflict resolution: `A_L = merge(L,H_A)`, `B_L = merge(L,H_B)`, then `I_AB = merge(A_L,B_L)`. Each clean merge uses `git merge-tree --write-tree`; deterministic synthetic commits retain the actual parent graph and do not move project refs. Conflicts at any stage remain unlabelled. Check `merge-base(A_L,B_L) == L` uniquely; otherwise exclude. Construct reverse integration `I_BA` too and require **tree equality** `tree(I_AB) == tree(I_BA)`; run attribution on **`I_AB` only**; divergent trees are `integration-order-ambiguous`, not a chosen favorable ordering. Record all source/tree/parent SHAs; a single-parent no-op normalization is explicit and never an invented edit.

**Own-base and common-base checks are both necessary (confirmed by Polaris).** Run the pinned oracle over the same union scope and environment for distinct states in `{B_A,H_A,B_B,H_B,L,A_L,B_L,I}` (cache identical source/config trees). First require frozen `delta(observe(B_i), observe(H_i), exact_path_map_i)` to be complete and empty for each PR. Then call frozen **`label(observe(L), {'A':observe(A_L), 'B':observe(B_L)}, observe(I), maps)`** unchanged. This second check rejects errors introduced merely by normalizing one head onto the later base. Deliberate over-exclusion: a PR red on its own base but repaired by default drift onto L still fails the first check, as D-Nat2 requires; do not silently rescue it. Never subtract B_A diagnostics from B_L or compare raw error counts/exits. Unsupported integrated errors, ambiguous identities, incomplete coverage and environment failures stay unlabelled. Positive: a new supported attributable integrated delta absent from both normalized tips; control: none. Two branches' minimal attribution must use the same diagnostic delta and leave-one-out states via frozen `minimal_attribution`; uncertain attribution is unlabelled.

Import **`benchmarks.s17.m3` byte-for-byte**, SHA-256 **`f9c64ecbfa9a7939303b697287a317ba84cf72d3ad23d86f17832e839f3ae5b5`**; retain the exact identity tuple `(rule,path,symbol,occurrence,root_cause)`. Reuse `identity.py`, `oracle.py`, matching and statistics without changing their S17 hashes or correcting exclusions after observing outcomes. Keep the existing M3 freeze manifest untouched. Any needed adapter change becomes a separate reviewed/frozen round, never a silent correction to S17 or S17b labels. Structural exclusions and own-base diagnostic deltas are retained alongside the final classification.

Production roots are fixed per repository before any checker run; production plus test scope is the frozen S17 rule. Pyright stays **1.1.407**, same basic config and fixed dependencies for all states. Prefer the existing complete oracle environment hash; absent dependencies remain unlabelled. Dependency metadata may inform a whole-candidate preregistration revision **only before checkpoint (1) and before any pair ledger**; no repository substitution afterwards, and no builds or labels may inform that revision. Do not install each PR's code, execute setup scripts, import its tests or call paid services. Open/dynamic module uncertainty cannot become a positive. Runtime-only exports unresolved by this oracle stay coverage gaps; no new runtime oracle is added in this round.

Run the installed immutable detector **only after labels**, against `L` and normalized tips `A_L,B_L`, with combined JSON output, cache disabled and fixed roots. Pin Polaris’s detector designation, exact commit/wheel/file map at S17b freeze **before any label**; changing that designation later requires a new round. Never use mutable worktree source. A synthetic pre-label test must verify raw SHA refs in combined mode; keep L/A_L/B_L and every synthetic integration reachable via local evidence refs in the disposable clone. This tests the same virtual states as the oracle. M1/M2 matching, distinct root-cause recall denominator and separate attribution remain unchanged. CW003 is a warning count, not precision/recall; CW004/PY-6 remains outside the type-checker stratum. Running only eligible cases means the emitted-prediction rate on excluded pairs is not estimable.

## Read-only acquisition calls and limits

Use REST **GET only** through the **existing `gh` login**, as directed by Polaris; never request new scopes, disclose tokens or send messages. Do not switch to another account or authentication mode to bypass a limit. Always spell `--method GET` when using `gh api -f/-F`, since field flags otherwise change its default method. [gh api manual](https://cli.github.com/manual/gh_api). Pin and record the **`gh` binary/version** (including `--paginate --slurp` support) and a supported `X-GitHub-Api-Version` before collection, record response date/ETag/rate headers, follow every `Link` page, and save only headers/metadata needed for provenance (no authorization headers). The PR-list endpoint does not provide the terminal-event window directly. Enumerate closed PRs by updated descending, derive possible overlap from list timestamps, drop provably out-of-window terminal records before ranking, and recheck the window against detail data lazily. Never stop on creation date. At the first sub-bound updated item, fetch **at least one further full page** (or exhaust the endpoint), recording violations `end_i >= lower_bound` among items with `updated_at < lower_bound`. Any violation requires continuing to the end or declaring collection incomplete at the ceiling. Pin the final page's Link header and total pages per repository, plus the extra-page result and all list snapshots. This is a declared pagination-consistency assumption with a checked tail sample, **not proof about every unseen item**.

N2 coverage choice for this bounded round: retain state=closed listing only and **disclose the hole**, rather than add a second open listing. A PR once closed in-window but currently reopened/open is absent and cannot be counted as a known exclusion. A reopened/reclosed PR whose final end is after the fixed cutoff is excluded even if an earlier closure was inside it; cutoff is no later than collection start. Neither limitation may be concealed by an “all historical overlapping PRs” claim. Track duplicates and changing metadata; required-page failures or unresolved pagination consistency make acquisition incomplete, never an implicitly complete candidate universe.

Repository detail supplies default branch/ID; pair-level detail/files/timeline calls are lazy and shared across reused PRs. After a metadata slot is selected, retrieve complete PR commits/objects for B1; a count/truncation mismatch consumes that slot as unresolved, not a new metadata-membership filter.

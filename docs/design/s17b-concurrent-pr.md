## Selection, before builds

Cohort: the eight public repositories below; **both PRs’ terminal events must be on or after `2022-01-01T00:00:00Z` and strictly before `collection_cutoff`**. Pin that lower bound and one exact UTC `collection_cutoff` in the accepted selector policy before requesting metadata; the cutoff does not advance during collection. There is no creation-date restriction: a PR opened before 2022 can qualify if its terminal event is in the fixed window. Include merged and closed-unmerged PRs and drafts; do not filter on CI, mergeability, review, title, conflict-related words, checker results or eventual success. Require the same target repository and its pinned default-branch name in both PRs. A PR redirected to a different base, reopened, or having incomplete lifecycle evidence is a selected-but-unlabelled uncertainty, not silently treated as continuously open.

For an unreopened terminal PR `i`, define `open_i = [created_at, end_i)`, with `end_i = merged_at` when non-null, otherwise `closed_at`. Validate `created_at < end_i`, terminal-state consistency and `merged_at <= closed_at` when both exist. Pair `A.number < B.number`; overlap means **`max(created_A, created_B) < min(end_A, end_B)`**. Equality is not overlap. A still-open PR at the fixed cutoff, missing/inconsistent timestamps or an unresolvable default-branch rename is not a member of this terminal-PR cohort; count metadata exclusions separately. A reopened PR is not represented by its outer interval; retain the selected uncertainty rather than infer missing episodes.

Both PRs must touch at least one `.py` path (current or previous filename on a rename), based on complete paginated PR-file metadata. File overlap is **not required**: a producer and consumer can change different files. Record shared-file/shared-module flags for later descriptions, never ranking. If Python-touching cannot be established from a truncated file list, retain a metadata-uncertain candidate in the ordering with no oracle label; do not assume it is non-Python. The PR-files endpoint caps responses at 3,000 files, so compare retrieved count against the PR detail's `changed_files`; no incomplete list is trusted. [GitHub PR-files contract](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests-files).

After the fixed terminal-window/base/Python filters, sort overlapping candidate pairs by **SHA-256 of `"s17b-v1|<repo-id>|<A>|<B>"` ascending**. Record `pair_order_seed = "s17b-v1"` and the exact encoding contract in policy before collection: `<repo-id>` is the stable numeric GitHub repository ID, and `<A>`/`<B>` are PR numbers with `A < B`, all canonical unsigned decimal without leading zeros; UTF-8 bytes, literal `|` separators, no quotes or trailing newline. Sort by digest bytes (equivalently lowercase hexadecimal), breaking a digest collision by numeric `(A, B)`. This outcome-blind seeded order replaces ascending PR-number sampling. Select the first **20 pairs per repository**, at most **160 total**, in **one round**, with no replacement for later fetch/build/conflict failures; stop at the cap even with zero positives. PR reuse across pairs is permitted, deduplicated only for source/oracle execution; do not treat dependent pairs as independent samples. A repository with fewer candidates contributes all it has. Freeze all selected pair numbers, URLs, lifecycle fields, file-list digests and rejection counts **before any repository oracle/build**. Retain the complete metadata candidate ledger so a reviewer can reproduce the cap and ordering.

## Immutable heads and default-branch context

Use disposable public clones outside the project worktree. Pin default-branch history once; perform no checkout, ref update or commit in crosswire itself. Fetch each selected unique PR with **`git fetch --no-tags origin refs/pull/<n>/head`**, immediately resolve `FETCH_HEAD^{commit}`, and save the object under a dedicated local evidence ref in that disposable clone. Never fetch `refs/pull/<n>/merge` as ground truth. Compare the fetched SHA with the pinned PR detail's `head.sha`; ref absence, permission/transport failure or a changed SHA is **unlabelled**, with no replacement or silently updated selection. A deleted fork must not trigger a fetch from an arbitrary supplied fork URL. Preserve an object bundle for audit if GitHub later removes a head. [GitHub's PR-head retrieval instructions](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/checking-out-pull-requests-locally).

Final heads are mandated by P3 but can contain work authored **after the overlap**. Record the overlap endpoints and each head's authored/committed times; never claim these trees actually coexisted. Commit times cannot reconstruct force-push histories. This stratum asks about final natural branches associated with concurrent PRs, under a virtual integration. Historical CI success is metadata, not oracle ground truth, and is never a selection requirement.

**Strict default snapshot rule (confirmed by Polaris):** using today's default HEAD can make a merged PR head its own merge-base and erase its change. For pair cutoff `c = min(end_A, end_B)`, reconstruct a default snapshot `D` before the earlier terminal event. The authoritative anchor is that earlier PR's API `merge_commit_sha`, verified on the pinned default first-parent chain. If terminal times tie, accept only an unambiguous earliest integration on that chain; unresolved chronology remains unlabelled.

- **True merge commit:** verify the integration commit and its parent/head relation in the pinned graph; **`D = first parent`**.
- **Squash merge:** when the PR's `merge_commit_sha` identifies its single-parent squash integration commit on the pinned default first-parent chain, **`D = that commit's parent`**. Verify the graph and the PR-to-integration-commit association. **Do not require its tree to equal a virtual result of applying the PR diff.** Such equality is not part of anchor eligibility.
- **Rebase merge, closed-unmerged PR, or otherwise unproven anchor:** record **`default-anchor-unresolved`**, keep the selected pair unlabelled and stop that pair. A single-parent commit alone does not distinguish squash from the last commit of a rebase merge; ambiguous merge-method evidence remains unresolved. Never interpret a rebase result's last commit as a whole-PR boundary.

There is **no timestamp-proxy cohort in this round**, and no replacement pair for an unresolved anchor. Timestamp overlap remains a selection criterion, not proof of default-branch ancestry.

Compute **each own base** `B_i = unique merge-base(H_i, D)` from pinned objects; missing/multiple bases or `B_i == H_i` are unlabelled (already contained or ambiguous). Record both bases and the default anchor. Require the bases to be ancestry-comparable: if `B_A` is ancestor of `B_B`, later base `L = B_B`, and conversely; equality is allowed. **Later means ancestry, not author/committer date.** Incomparable bases are unlabelled; never invent a new merge baseline. Reject identical/ancestral heads and cross-contamination: if another selected PR's changes are already included in a head, it is not an independent two-branch experiment. Require graph evidence; unresolved squash/cherry-pick equivalence is unlabelled, not guessed from messages. Record this as a separate coverage limit.

## Integration and exact M3 reuse

Construct states using pinned native Git merges, never textual patch concatenation or conflict resolution: `A_L = merge(L,H_A)`, `B_L = merge(L,H_B)`, then `I_AB = merge(A_L,B_L)`. Each clean merge uses `git merge-tree --write-tree`; deterministic synthetic commits retain the actual parent graph and do not move project refs. Conflicts at any stage remain unlabelled. Check `merge-base(A_L,B_L) == L` uniquely; otherwise exclude. Construct reverse integration `I_BA` too and require equal trees; divergent trees are `integration-order-ambiguous`, not a chosen favorable ordering. Record all source/tree/parent SHAs; a single-parent no-op normalization is explicit and never an invented edit.

**Own-base and common-base checks are both necessary (confirmed by Polaris).** Run the pinned oracle over the same union scope and environment for distinct states in `{B_A,H_A,B_B,H_B,L,A_L,B_L,I}` (cache identical source/config trees). First require frozen `delta(observe(B_i), observe(H_i), exact_path_map_i)` to be complete and empty for each PR. Then call frozen **`label(observe(L), {'A':observe(A_L), 'B':observe(B_L)}, observe(I), maps)`** unchanged. This second check rejects errors introduced merely by normalizing one head onto the later base. Never subtract B_A diagnostics from B_L or compare raw error counts/exits. Unsupported integrated errors, ambiguous identities, incomplete coverage and environment failures stay unlabelled. Positive: a new supported attributable integrated delta absent from both normalized tips; control: none. Two branches' minimal attribution must use the same diagnostic delta and leave-one-out states via frozen `minimal_attribution`; uncertain attribution is unlabelled.

Import **`benchmarks.s17.m3` byte-for-byte**, SHA-256 **`f9c64ecbfa9a7939303b697287a317ba84cf72d3ad23d86f17832e839f3ae5b5`**; retain the exact identity tuple `(rule,path,symbol,occurrence,root_cause)`. Reuse `identity.py`, `oracle.py`, matching and statistics without changing their S17 hashes or correcting exclusions after observing outcomes. Keep the existing M3 freeze manifest untouched. Any needed adapter change becomes a separate reviewed/frozen round, never a silent correction to S17 or S17b labels. Structural exclusions and own-base diagnostic deltas are retained alongside the final classification.

Production roots are fixed per repository before any checker run; production plus test scope is the frozen S17 rule. Pyright stays **1.1.407**, same basic config and fixed dependencies for all states. Prefer the existing complete oracle environment hash; absent dependencies remain unlabelled. Dependency metadata may be inspected before freezing to reject an unsuitable whole candidate in an explicit preregistration revision; no builds or labels may inform that revision. Do not install each PR's code, execute setup scripts, import its tests or call paid services. Open/dynamic module uncertainty cannot become a positive. Runtime-only exports unresolved by this oracle stay coverage gaps; no new runtime oracle is added in this round.

Run the installed immutable detector **only after labels**, against `L` and normalized tips `A_L,B_L`, with combined JSON output, cache disabled and fixed roots. Pin the detector source revision/wheel/file map at S17b freeze (Polaris designates the accepted current revision then; do not silently reuse mutable worktree code). This tests the same virtual states as the oracle. M1/M2 matching, distinct root-cause recall denominator and separate attribution remain unchanged. CW003 is a warning count, not precision/recall; CW004/PY-6 remains outside the type-checker stratum. Running only eligible cases means the emitted-prediction rate on excluded pairs is not estimable.

## Read-only acquisition calls and limits

Use REST **GET only** through the **existing `gh` login**, as directed by Polaris; never request new scopes, disclose tokens or send messages. Do not switch to another account or authentication mode to bypass a limit. Always spell `--method GET` when using `gh api -f/-F`, since field flags otherwise change its default method. [gh api manual](https://cli.github.com/manual/gh_api). Pin a supported `X-GitHub-Api-Version` before collection, record response date/ETag/rate headers, follow every `Link` page, and save only headers/metadata needed for provenance (no authorization headers). Queries below are design examples, not executed requests:

```sh
gh api --method GET /rate_limit
gh api --method GET "repos/$OWNER/$REPO"
gh api --method GET --paginate --slurp "repos/$OWNER/$REPO/pulls" -f state=closed -f sort=updated -f direction=desc -F per_page=100
gh api --method GET "repos/$OWNER/$REPO/pulls/$N"
gh api --method GET --paginate --slurp "repos/$OWNER/$REPO/pulls/$N/files" -F per_page=100
gh api --method GET --paginate --slurp "repos/$OWNER/$REPO/issues/$N/timeline" -F per_page=100
gh api --method GET "repos/$OWNER/$REPO/commits/$MERGE_SHA"
git fetch --no-tags origin "refs/pull/$N/head"
```

The PR-list endpoint does not provide the terminal-event window directly: enumerate closed PRs by `updated` descending and locally filter `end_i` into `[2022-01-01T00:00:00Z, collection_cutoff)`. Do **not** stop on an old creation date; long-lived PRs created earlier can qualify. A complete page whose `updated_at` values are all strictly before the terminal lower bound permits stopping only with validated timestamp consistency (`updated_at >= end_i`) and ordering; if that cannot be established, continue to the end or declare metadata acquisition incomplete at the ceiling. A future selector implements bounded page-by-page collection rather than blindly fetching all pages in the example. Repository metadata supplies default branch/ID; PR detail supplies terminal times/head SHA/base identity/changed-file count; files establish Python touch; timeline verifies reopening/base-history uncertainty; commit detail can validate the proposed default integration anchor. Authoritative history still comes from the pinned Git graph. Reuse cached responses per PR across all pairs. [PR REST contract](https://docs.github.com/en/rest/pulls/pulls), [timeline REST contract](https://docs.github.com/en/rest/issues/timeline), [commit REST contract](https://docs.github.com/en/rest/commits/commits).

Metadata completeness is a prerequisite: if a required page fails or lifecycle/base history cannot be established, record the limitation and do not infer candidates from a partial list. Do not use search APIs' capped result sets as a complete pair universe. Read `X-RateLimit-*`/`Retry-After`, make serial requests with cache, and checkpoint on rate exhaustion rather than switching credentials to evade limits. [GitHub rate-limit contract](https://docs.github.com/en/rest/rate-limit/rate-limit). Accepted ceilings: **1,500 GET requests and 2 GiB Git transfer** for the acquisition round, plus **90 minutes serial measurement**, using the existing read-only `gh` login without new scopes. These limits and pair order are frozen before collection. Hitting a ceiling produces a published incomplete cohort, not a replacement cohort or a claim of exhaustive sampling.

# S19 Go development corpus — proposed design, Deneb

**Design only; no collection or build.** Applies PLAN P3 D-Nat2 to Go, with the frozen [Go contract](../languages/go.md), QUALITY/Q1 and matching M1/M2. This is **natural branches, virtual integration; development only**, separate from S19a recorded merges, Go conformance/mutations, Python S17b and any holdout. P7 acquisition remains subject to Vega review; this design does not authorize its use or refresh a checkpoint. No claim of current repository activity, dependency availability or Go detector readiness is made.

## Candidate selection before any request or build

Freeze eight candidates in the order below, chosen for small library production surfaces, distinct domains, established PR histories and module-era sources. The first five reuse S19a's URL/domain knowledge and current-head build evidence; that prior development evidence biases this sample. The last three are proposals based on library scope, **not verified concurrency, module/dependency or build claims**. Do not replace a candidate because of low yield, a failed build or a missing dependency.

| Public repository | Domain | Expected risk, to record rather than optimize away |
| --- | --- | --- |
| [go-chi/chi](https://github.com/go-chi/chi) | HTTP routing | Old recorded merges predate modules; PR refs may recover recent divergent histories |
| [spf13/pflag](https://github.com/spf13/pflag) | CLI parsing | S19a had readonly-module failures; do not repair historical module files |
| [google/uuid](https://github.com/google/uuid) | Identifiers | Small surface and low concurrency may produce few eligible pairs |
| [etcd-io/bbolt](https://github.com/etcd-io/bbolt) | Embedded storage | OS-specific/mmap code and build context may limit supported proofs |
| [miekg/dns](https://github.com/miekg/dns) | DNS protocol | External dependency versions and historically unsupported module roots |
| [gorilla/mux](https://github.com/gorilla/mux) | URL dispatch | Overlaps Chi's domain; potentially sparse recent changes |
| [rs/zerolog](https://github.com/rs/zerolog) | Structured logging | Generated/OS-specific code and optional sinks |
| [julienschmidt/httprouter](https://github.com/julienschmidt/httprouter) | Radix routing | Low activity; sparse independent producer/consumer changes |

This gives at least five distinct domains without asserting five **eligible** repositories. Aim for ≥5 eligible repository clusters; publish an insufficient pilot if fewer qualify. Before acquisition, Polaris/Vega approve the fixed URL/order/root proposal and pin controller Python/Git/gh, GitHub API version, exact cutoff, seed, budgets and detector source commit. During read-only metadata acquisition, pin numeric repository ID, default branch and default SHA; checkpoint (2) retains selected PR numbers, detail/file/timeline/commit-list hashes, final/effective head SHAs and Git bundles. No SHA is invented in this design; none is looked up now.

Use both terminal events in `[2022-01-01T00:00:00Z, collection_cutoff)`, with cutoff fixed no later than acquisition start. Reuse the exact half-open open-interval overlap, canonical numeric IDs, seeded `s17b-v1|<repo-id>|<A>|<B>` hash ordering, terminal-event proof/tolerance, lifecycle rejection and metadata short circuit from S17b revision 3 plus accepted fixes. No CI, mergeability, title, diagnostic, file-overlap or eventual-success filter. Both PRs must touch a current or previous **production `.go` path**, excluding `_test.go` and `vendor/`, proved from complete file lists; record test-only changes separately. Build constraints/nested-module status are not inferred from filenames alone to select favorable cases.

Enumerate possible overlap from list data only; walk the hash order until **20 metadata-passing pairs per repository, ≤160 overall**, or the fixed allocation/order ends. Pre-ordering retains only the existing provable window/non-overlap exclusions. Metadata failures consume no slot; module/context/graph/environment/textual/M3 failures **after selection consume their slot**, with no replacement. Module-era means a real module is present in every required own-base/common-base/tip/integration state, not merely at today's HEAD. Module absence is a post-selection exclusion; never create a synthetic `go.mod`, advance the historical base or search another pair to compensate.

## Reuse boundaries and changes that need a new freeze

| S17b component | S19 action |
| --- | --- |
| GETs, endpoint allowlist, pinned numeric pagination, request/cache lineage, isolation, incremental metadata, transfer accounting | Reuse the reviewed P7 implementation, version/hash pinned; no Go-specific networking |
| Pair enumeration/hash/window/caps/lifecycle/default-base checks | Same contracts and test vectors; no change to Python's frozen selection module |
| Python-touch metadata predicate | Separate Go adapter/predicate (`.go`, production exclusions), independently hashed/tested before acquisition; do not monkeypatch the Python filter or rewrite its hash |
| Anchors, own bases, B2, native integration | Reuse unchanged graph/pipeline functions: true-merge/rebase/squash proof, no timestamp/message proxies; both integration orders must have identical trees |
| Pre-update fallback | Same single proven default-merge crossing and PR-membership/B2 tests; no older-candidate search; final-head and pre-update strata separate |
| M3 | Import `benchmarks/s17/m3.py` byte-for-byte; Go observations supply explicit `supported` identities, so Python's default supported-code set is never used |
| Oracle/identity/matching/scope | New Go adapters, independently frozen and audited; Python AST identity and the Python-only M2 correction are not Go implementations |
| Detector | Installed `[go]` wheel from a pinned committed T25/T26 revision; no worktree source. Before it exists, `detector: not available`, no metrics/pass |

A clean way to avoid changing `selection.py` is a separately versioned Go selector adapter that copies the accepted selection contract and swaps only the file-language predicate, with equivalence tests over identical metadata and explicit Go-path tests. Any generalization instead needs Vega's review and a new acquisition checkpoint; freeze its implementation before a real Go pair is selected. Reuse machinery, not Python-specific labels or historical Python cohort membership.

The single shared request allocation remains **127 metadata +60 commit-list GETs per repository**, never rolled or borrowed (1,496 allocated under 1,500 global); retries across resumes count, cached responses do not. Retain the reviewed ≤3-attempt request policy, 120s PR /60s other GET timeout, ≤300s individual service wait, 900s total waits, PR health cap and terminal-health rules. Git uses the same **2 GiB cumulative proxy** including default histories and PR heads. A fetch can overrun its remaining proxy allowance once; publish the measured overage and stop. Unknown partial transfers remain incomplete, without guessed bytes. Dependency-cache bytes below are a separate preregistered resource, never silently counted as Git transfer.

## Immutable graph and module scope

Retrieve only pinned `refs/pull/<n>/head`, compare with the API head SHA, bind local evidence refs and preserve bundles. Stale/unavailable heads remain unlabelled. Reuse B1 authoritative default anchoring, unique/comparable own bases and B2's three contamination proofs **before integration**. Record ancestor-equivalent/shared patch/merge-containing-range exclusions; never relax them to increase yield. Final heads can postdate the overlap, and later authors may already have repaired earlier changes: no historical prevalence claim. Pre-update rescues were adopted after a Python graph exclusion with unknown oracle status; disclose inherited design provenance, not a claim of Go outcome blindness from first principles.

For each selected pair, enumerate tracked trees and `go.mod` boundaries without executing repository code. Propose one root module per candidate (repository root); nested modules are outside that root and reported as gaps. Package identity is **module path + directory**, package name from the package clause, exported Unicode Lu, import alias/shadowing/file scope respected; `internal/` accessibility is part of identity. The module path/root must be unambiguous and unchanged for any supported proof; changed module identity or affected first-party `replace`/`go.work` links are gaps. No workspace creation, go.mod/go.sum edits, generated sources, test stubs or project setup scripts.

Record the full per-state production package/file inventory and the union of relevant packages/use sites across `B_A,H_A,B_B,H_B,L,A_L,B_L,I_AB` (and `I_BA` for order/tree verification). `go build ./...` discovers production packages in the fixed root; list output must explain each tracked file's inclusion or exclusion. Deleted/moved package files are expected absences with tracked tree proof, not a license to shrink the oracle silently. `_test.go`, vendor/nested modules and constraint-dependent files are counted as excluded. Tests never decide labels. A compiler build may include an active OS-specific file; any **supported proof** depending on tags, OS/arch suffixes, cgo or uncertain generated code is unlabelled/gap under the contract. Do not delete these files to make the oracle match the syntactic analyzer.

## Oracle and dependency preparation, before checkpoint (2)

Pin **Go 1.27.1**, fixed **darwin/arm64**, `GOMAXPROCS=2`, no custom tags, `GOTOOLCHAIN=local`, `GOENV=off`, `GOWORK=off`, `CGO_ENABLED=0`, `GOTELEMETRY=off`, isolated fixed `GOCACHE/GOMODCACHE/GOPATH`, C locale and UTC. Hash go/compiler/linker, stdlib/toolchain manifest, target, go/types code table, helper source/binary and controller environment. Version mismatch, unsupported toolchain directives or a needed generator is an environment exclusion; no automatic toolchain download.

The semantic command is exactly **`GOFLAGS=-mod=readonly go build -gcflags=-e ./...`**. Prepare all finite required module/version contexts before observing builds: after graph integration/scope inventory, run only the preregistered public `go mod download -json` setup in disposable copies. Cache successful setup by exact module/sum/context hashes. Snapshot and restore original module-file bytes after setup; a later readonly build must leave them unchanged. Hash downloaded archives, `.mod/.info`, checksums and extracted first-party-independent modules, excluding volatile locks/build-cache state. Do not invoke `go get`, `go mod tidy`, module upgrades, private credentials or repository scripts. Proposed separate dependency cap: **1 GiB cache growth and 15 minutes serial setup**, with per-context timeout 180s; failures consume the selected slot, no later repair after diagnostics. This is a proposed ceiling needing Polaris's approval, not an active policy.

At measurement, set **`GOPROXY=off GOSUMDB=off GOVCS=*:off`**, clear inherited private/proxy flags and run every state under the exact same recorded environment/cache snapshot. A new module graph created by integration must have its declared dependencies prepared before checkpoint (2), or stay unlabelled. Dependency failure/missing external package never becomes GO-2. No setup download occurs after the first oracle observation. Read/cache only; do not execute candidate binaries or tests.

Capture `go vet ./...` as an explicitly budgeted **separate channel**, with its raw/category/coverage output and no influence on labels or supported recall. Vet may inspect tests the production build omits; mark that scope separately. A timeout/missing test dependency there does not invalidate an otherwise complete production build, and vet is never used to infer green tips. Conservative first pilot option: omit vet execution, publish `not run` instead of claiming coverage; Polaris chooses before freeze.

## Go observations, M3 and matching

The compiler build decides semantic validity. Run the pinned `go list -e -deps -export -json ./...` and independent go/types helper only to recover code+position+AST evidence; record package-loading failures and uncovered/dependent packages. The existing S19a/S16 helpers are starting points, **not complete natural-corpus identities**: they lack stable occurrence/root-cause IDs and declaration-pair locations for arbitrary source. Add those and package-error/parse completeness checks before any label. A build/helper disagreement, unjoined position, masked dependent package, uncertain import owner or multiple unrelated new roots stays unlabelled. English prose is audit-only, never the categorizer. Populate `go/types.Info` Uses/Defs/Selections/Scopes/Implicits so a selector is tied to an actual `types.PkgName`, not an import-spelling guess; lexical shadowing and package-clause names must survive normalization. For GO-4 retain declaration identities and compiler-related locations; any secondary unused-import note may collapse only into its proven duplicate-import root, never by message similarity.

Reuse the frozen M3 tuple **(rule, repo-relative path, symbol, occurrence, root cause)** with Go code/category in `rule`, module/package-qualified identity in `symbol`, and scope/AST-based occurrence/root IDs. Diagnostic position locates a syntax site; line/column alone never defines its identity across states. Explicit one-to-one Git rename/path maps handle moves; repeated indistinguishable sites, many-to-one maps and uncertain symbol ownership are unlabelled. Normalize duplicate compiler notes and dependent cascades to one root. Retain every original position for audit; do not drop extra roots to meet the one-root contract.

Conservative pilot eligibility requires green production builds for own bases, common later base and individual states, in addition to both frozen M3 own-base and common-later-base checks. Go build masking makes non-green baselines hard to subtract completely; leave them unlabelled rather than claiming a complete partial diagnostic delta. This is stricter oracle eligibility **after selection**, no replacement or changed M3. `Observation.supported` explicitly contains only correctly classified GO-1…GO-4 roots. A positive is a new supported integrated diagnostic absent from both eligible tips, with minimality confirmed by leave-one-branch-out states; a control has no new diagnostic. New unsupported/ambiguous diagnostics are unlabelled, not controls. S19 remains two-branch natural replay; N-way volume belongs to separately declared mutations.

| Type | Oracle evidence and detection match key | Critical negatives/unknowns |
| --- | --- | --- |
| GO-1 | `UndeclaredImportedName` at a first-party `pkg.Name` use; same missing exported owner/symbol, use-file and stable occurrence | External/std imports, unexported names, fields/methods or shadowed `pkg` do not prove exported-name removal |
| GO-2 | First-party directory absent/moved in Git inventory plus import-loading failure at the confirmed import; **module-qualified missing package path + use-site file** | Missing downloaded dependency, external module, module-path change, internal-access or cycle error is not package removal; no line/symbol requirement imported from PY-2's old bug |
| GO-3 | `WrongArgCount` joined to actual top-level function declaration/call and call occurrence | Grouped/unnamed/variadic/explicit `...` cases tested; multi-value args, conversions, callable variables, methods/generics remain unknown |
| GO-4 | Duplicate declaration category plus the **unordered declaration pair**, package/name or receiver-qualified `T.M`, and both locations | Same/cross-file, identical declarations, file-scoped duplicate import names included; `_`/`init` exempt; local shadowing, different receivers/packages/files for import scopes are controls; constraints unknown |

Derive predicted language/rule/type from the detector's own emitted rule and resolved entity, never the known case label. CW001/CW006 may describe GO-1/2, CW002/CW006 GO-3 and CW003/CW006 GO-4, per the frozen contract; ambiguous entity evidence stays unlabelled for matching, with reason. CW006 is not a synonym for a particular Go type. GO-4 CW003 is an **error** and enters semantic detection counts; Python CW003 remains a separately reported warning. Duplicate import bindings map to **GO-4**, correcting the old census mapper (counts remain zero); unused/missing bare imports stay GO-7 observations only. GO-6/7/8/9 get separate candidate observation counts; GO-5 stays deferred, never added to supported recall.

Apply matching M1/M2 one-to-one, including every attributable root and extra predictions (FP), separate exact culprit-set attribution, and detector crashes/timeouts as FN on supported labelled positives without shrinking the denominator. GO-2's missing-package/use-file identity and GO-4's declaration-pair identity need predeclared, separately hashed adapters/tests before labels; propose these as Go contract specializations, **not edits to frozen Python M2 code**. No post-label matcher change can silently replace the raw scores.

## Freeze sequence, stops and reporting

1. **Review/checkpoint (1), before API:** freeze repository roster, Go file predicate/order contract, cutoff/seed/ceilings, reviewed P7 transport/lineage, graph/M3 and metadata code; Polaris creates authorization. Do not reuse Python's authorization for a Go cohort. Log all acquisition attempts; allow only reviewed apparatus-only fixes with predecessor checkpoints and unchanged selection/semantic rules.
2. **Acquisition/preparation:** replay successful cache first, request missing metadata only, retain selected slots and bundles, construct deterministic native virtual states, inventory scope and dependencies without compiler/detector observations. Modules absent, unsupported contexts, unresolved anchors, B2 or textual conflicts are consuming exclusions. No case is a positive/control yet. Do not advance to semantic observation if the graph or setup freeze is incomplete.
3. **Audited checkpoint (2), before the one measurement:** seal all selected/unattempted/rejected ledgers, object/tree SHAs, exact state scope/config, dependencies, oracle/helper/identity/matching and runtime hashes, detector wheel/install map and durable measurement driver. Pin serial wall budget **5,400s**, per-command timeout180s, crash/no-rerun journals and report-only export. Vega audits; Polaris authorizes. A failure during the one measured attempt is published as-is, not repaired/resumed for better labels.
4. **Report development-only results:** per repository and final-head/pre-update stratum, selected/evaluated/eligible/unlabelled/unattempted, metadata/graph/context/environment reasons, GET class/retries/waits/bytes, PR reuse and anchor/rescue counts. Per GO rule/type and mode report TP/FP/FN, prediction/positive denominators, Wilson intervals and repository-clustered intervals only with ≥5 eligible clusters; fewer than 20 predictions/positives is insufficient. Publish every FP/FN root cause, attribution separately, candidate/vet/textual/gap counts separately. Never mix S19a, mutation, Go/Python or holdout denominators.

Expected yield is **unknown**: S19a's zero positives and ancestor-equivalent merges motivate concurrent PRs but predict no rate. Even 160 selected pairs may yield zero supported positives or fewer than five eligible repositories. A planning sensitivity example of 10–25% eligible gives 16–40 labelled pairs **if all slots fill**, not a forecast or sample-size guarantee. Stop at the preregistered caps/budgets, not the first good score/positive; no supplements to reach a gate. Volume/minimums belong to mutation and later explicitly preregistered rounds. Freeze the random audit draw before labels; Vega checks 10% plus every FP and ambiguous mapping.

Large metadata/bundles/raw build and detector outputs follow D-Ev1: sanitized external archive and committed SHA-256, policies/freezes/compact aggregates in git, optional `CROSSWIRE_EVIDENCE_DIR` audit tests. No absolute local paths or host tar user/group fields. Keep all holdout material untouched and unmeasured.

Before authorization, synthetic tests must cover numeric pagination/resume/foreign IDs and exception persistence; metadata language-predicate equivalence and module-era consuming exclusions; all B1/B2/default-update shapes; unchanged M3 subtraction on Go identities; offline missing external dependency versus first-party GO-2; multi-module/replace/go.work/build-tag/cgo gaps; package-clause versus directory and alias/internal/Unicode identities; every GO-3 arity edge; all GO-4 declaration/import/receiver/exemption pairs; stable identities under line shifts/renames/duplicate sites; compiler/helper masking and multi-root exclusion; GO-2 M2-like file/package key; emitted-type classification/CW006, detector errors and no-rerun measurement journal. Use S16 smoke expectations and independent compiler evidence, never crosswire output as an oracle.

**Decisions requested from Polaris before any implementation/freeze:** approve the fixed eight-candidate roster and proposed dependency-only ceilings; choose captured vet versus explicit omission; approve conservative green Go baselines and GO-2/GO-4 matching specializations. Defaults here are no collection, no vet claim, unchanged M3, stricter unlabelled eligibility and no source/plan edits. These are proposals; the frozen GO-1…GO-4 support set is unchanged.

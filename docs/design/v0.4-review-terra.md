# v0.4 implementability review — Terra

- Freeze the exact JSON keys and schema placement for hints, repro, coverage and limitations;
  plan blockers and SARIF/GitHub/text need consistent semantics, not just JSON check reports.
- A repro is exact only when culprit enumeration is exact and order is preserved; skipped branches,
  target-owned references, shell quoting, source roots and inexact bounds need explicit handling.
- Hint only when evidence supports it: required positional-only arguments are not keywords;
  Django's next free number must inspect the integrated directory, not merely one branch.
- Count distinct unsupported sites and parse failures deterministically across caches and trials;
  report bounded examples and avoid attributing repeated trial scans to user-visible coverage.
- Define how partial coverage interacts with bounded coverage and with exit codes; silence cannot
  mean complete Python semantics when dynamic imports or unsupported constructs were skipped.
- Git bare repos, shallow boundaries, non-UTF-8 filenames and binary/oversize blobs need explicit
  contracts and tests; size must be checked before reading or decoding the whole blob.
- Schema versioning must cover changed v1/v2 fields and plan mode, and schema files must be
  included and retrievable from both wheel and source distribution without network access.
- T20 should compare deferred-branch outcomes before and after the selected step, including
  skip status and error keys; changed diagnostics alone do not establish an actual improvement.
- Keep gallery deferred until Sol's public development corpus is available; avoid seeing holdout.

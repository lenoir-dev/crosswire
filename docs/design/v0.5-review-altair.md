# v0.5 implementability review — Altair
Reviewed draft `bbae204` against released 0.4.0 source (`3be5221`); implementation/tests not changed or run.

- **Verdict: direction sound, protocol and Go scope not ready to freeze.** T21 is feasible as a mechanical extraction; T25/T26 need package-level analysis and narrower proof obligations first.
- `resolve(...)->Verdict` loses information already required from `state.Resolution`: return status, resolved binding/candidates, reason, consulted files, context dependencies and gaps. Culprit search needs evidence from both states, including removed files and changed manifests.
- Make `resolve(snap, use, ctx)` caller-aware: module/name alone cannot enforce Go `internal/`, unexported access or later Java visibility. Represent package imports as uses too, including Go blank imports; specify module-existence resolution separately from member resolution.
- Define `Snapshot` as immutable Git-tree access through core-provided reads/listing; `context` must be recomputed for base, tips and virtual states. Never read working-tree manifests, invoke language tools or follow external replacement paths at runtime.
- Replace the implicit single-symbol map with bindings containing multiple declarations, guards and opaque signature payloads; Go variants and Java overloads cannot inhabit today's `dict[name, Symbol]`. Include visibility/span and language-qualified module/symbol keys throughout summaries, indexes, interaction filters and deduplication.
- Reserve adapter-owned name normalization, namespace discrimination and resolution-context payloads for TS value/type exports and tsconfig/package conditions, Java overload candidates/classpaths, and PHP Composer/namespace aliases. Keep these out of core string matching; do not promise type-dependent resolution from syntax alone.
- `check_call(use, old, new)` should accept binding sets and prove old-call validity before new-call breakage; unknown on either proof suppresses the conflict. Preserve each mode's existing choice of baseline; move `binding_error`/`keyword_hint` behind Python without changing reason text.
- Add package/module aggregation before `api_changes`: `_Analysis.side()` currently diffs each changed file and overwrites `modules[newmod]`. Moving `F` between Go files must produce neither removal nor addition; unchanged sibling declarations and references must participate.
- Add adapter operations for definition comparison and integrated-state rules. `PairContext.definition_dump`, `coverage._sites`, `combined._broken`/`_location`/`target_candidates`, `planner._migration_findings` and `diagnostics.migration_hint` all contain Python semantics beyond the proposed extraction methods.
- `rules()->list[Rule]` needs explicit pairwise/state hooks and evidence contracts. Combined currently retains pairwise CW003/CW004; Go redeclarations must be rechecked in final/trial states so a third branch deleting one declaration can repair them and planning can recognize that repair.
- Define parse results/gaps for every extraction method, not just resolution; tree-sitter recovery (`has_error`/missing nodes) must yield unknown for affected proofs, never confident absence. Do not swallow adapter bugs as malformed user code. See [Node API](https://tree-sitter.github.io/py-tree-sitter/classes/tree_sitter.Node.html).

- **T21 gate:** byte-identical CLI stdout/stderr/exit codes is realistic; every internal object is not automatically identical. New `Symbol` fields leak through `asdict` captures; retain legacy facades/projections explicitly, rather than refreshing old snapshots or weakening the CLI gate.
- Sequence T21a: Deneb freezes full 0.4 CLI bytes (all supported modes/formats, coverage, hints, parse warnings, cache on/off); keep existing `python_analyzer`/`StateIndex` import shims. Existing historical projection tests alone do not establish complete 0.4 byte equality.
- Sequence T21b: move Python parsing/resolution/call logic with delegation shims; then dispatch engine, combined and planner through adapters in small independently green steps. Preserve reference multiplicity, ordering, guarded definitions, re-export depth and scoped coverage; Deneb/Vega verify before deleting shims.
- Sequence T21c: version adapter API plus cache schema; add adapter payload codecs and context/configuration fingerprints to disk AND run-cache keys. Leave renderers unchanged; defer telemetry, language fields and missing-extra reporting until the equality checkpoint is accepted.
- Keep T22 separate: `git.merge_tree_conflicts` still launches per pair, while direct-parent/merge-base memoization already exists. Specify fixtures and p95 for the 2× target; capability-check batching against minimum Git 2.38 and retain a fallback, rather than assuming one supported batch command.
- T23 lacks a real trial limit: define culprit trials versus planner-state evaluations, cache-hit accounting and run-wide counting without nested double counts. Implement an enforced budget or report limit as unavailable; update offline schemas and goldens only after T21.
- T24 should use accepted per-cell S14 RSS budgets and add a blocked/search-heavy 30-branch case before cache redesign: existing clean fixtures do not exercise the retained `AnalysisRun.indexes`, module caches and planner `states` at worst-case growth.

- **Go module model:** start with one unambiguous module; support a module rooted below repo root, stop at nested `go.mod`, and treat missing/malformed/ambiguous manifests as gaps. A `go.mod` edit must invalidate/revisit package identities and target callers even when no `.go` file changed. See [module reference](https://go.dev/ref/mod).
- Do not guess default import bindings from directory basename: use the imported package clause (e.g. a `/v2` path), explicit aliases and lexical shadowing. Keep imports file-scoped and declarations package-scoped; Unicode export checks must use category Lu. See [Go spec](https://go.dev/ref/spec#Declarations_and_scope).
- `internal/` needs the importing package's permitted subtree checked before a use is considered valid. Defer new visibility-conflict detection with a gap if necessary, but do not resolve an inaccessible package as valid. See [internal packages](https://pkg.go.dev/cmd/go#hdr-Internal_packages).
- Resolve first-party package absence using prior-state ownership; preserve evidence when the last file/directory disappears. Do not let GO-2 degrade into external `unknown` simply because the package is absent in the final tree (`combined._broken` currently supplies a Python-specific workaround).
- **Build constraints are not interchangeable with Python guards.** Include `//go:build`, legacy `// +build`, filename GOOS/GOARCH constraints and cgo context. `f_linux.go:F` plus `f_windows.go:F` is not a redeclaration; presence in some variant does not prove a call valid in another. See [build constraints](https://pkg.go.dev/cmd/go#hdr-Build_constraints).
- Cut GO-5 and guarded GO-3/GO-4 from initial supported recall unless a declared build context and guard-aware proofs are designed first; emit gaps for those cases. Never compare one arbitrary variant's signature or report mutually exclusive definitions as errors.
- GO-3 needs grouped/unnamed parameter counts, minimum variadic arity and explicit `...` call handling. `pkg.F(g())` may expand multiple results: without proven result arity it is unknown. Distinguish functions from type conversions, callable variables and generic calls; keep unsupported cases out of the denominator. See [calls](https://go.dev/ref/spec#Calls).
- GO-4 must report identical declarations in different coexisting files: Python CW003's equal-AST suppression is wrong for Go. Exclude `_` and repeatable `init`; retain declaration locations rather than collapsing duplicates into one symbol. Restrict the first implementation to provably coexisting files. See [initialization](https://go.dev/ref/spec#Package_initialization).
- Freeze production-only analysis for v0.5b: exclude all `_test.go` definitions AND uses, report scoped test-analysis gaps, and defer package-test/external `p_test` variants. Separate build diagnostics from vet/test diagnostics in the corpus oracle; pin its build context.
- Exclude `vendor/` from first-party indexing; imported vendored targets are unsupported gaps. For `replace`/`go.work`, classify affected unresolved first-party links as gaps, not ordinary external unknown; support in-repo remapping deliberately or defer it. An unrelated external import alone remains outside scope.

- **Packaging:** declare pinned compatible `tree-sitter` AND `tree-sitter-go` in `[project.optional-dependencies].go`; `uv.lock`/dev groups do not constrain users' pip installs. Lazy-load Go; keep extension recognition available without importing its parser, and distinguish absent extras from broken installed bindings.
- Validate grammar/runtime ABI plus clean wheel/sdist installs using binary-only dependency resolution across claimed Python/OS/architecture support; Linux/macOS alone is narrower than V10's promise. Check core-only imports/CLI independently; availability must not be inferred from the lockfile. See [grammar distributions](https://pypi.org/project/tree-sitter-go/) and [runtime ABI](https://tree-sitter.github.io/py-tree-sitter/classes/tree_sitter.Language.html).
- T27 is an additive contract task: define language-qualified finding identities, per-language coverage aggregation, missing-extra file-count scope and schema projections after T21. Scope it to changed/consulted/candidate files, preserving v0.4's rule against scanning unrelated code.
- **Requested split:** freeze protocol/evidence and package aggregation first; land Python equality before T22/T23; deliver unconditional single-module GO-1–GO-4 first, with guarded analysis/workspaces/test packages explicitly deferred. S16 templates need language capability declarations, not forced Go equivalents of Python star imports/open modules.

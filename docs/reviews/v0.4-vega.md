## Details

### V4-01 major — coverage collection costs 7× and invalidates the performance claim

`coverage.inspect()` walks **every** tracked file of every commit in `[target, *tips, merged]` (`coverage.py:56-92`), reads
it, parses it (`_sites`), then resolves **every reference** of it through a per-commit `StateIndex`. It runs in all three modes
(`engine.py:286`, `combined.py:435`, `planner.py:231`). `_module_data` (`state.py:33-47`) is an LRU capped at 8 192 entries; on a
9 051-file repository a sequential scan evicts each entry before the next commit needs it (0 % hit rate): cProfile shows
`_build_module_data` called 143 984 times (≈ 16 tips × 9 k files) and `coverage.inspect` = 19.7 s of 20.4 s.

Repository: 9 051 files, 16 independent branches each touching 2 files (the v0.3 benchmark), warm cache, same machine, load ≈ 3:

| mode | v0.3.1 | v0.4.0 |
| --- | --- | --- |
| `check --target main` (pairwise) | 1.7 s | **13.0 s** |
| `check --target main --combined` | 4.8 s | **14.0 s** (3.2 s with `coverage.inspect` stubbed out) |
| `plan --target main` | 95 s | **14.9 s / 16.6 s / 16.9 s** (three runs; R1 budget ≤ 15 s; Altair's report: 7.1 s) |

QUALITY §4 forbids > 10 % regressions without a waiver; pairwise regresses 7.6×. Fix: scope coverage to what the run actually
analysed (files changed by any branch + the sites of references that were resolved, see V4-02), key `_module_data` by blob OID
and size it ≥ the tree (or make it unbounded per run), and compute coverage once per run, not per state/pass.

### V4-02 major — `partial` is constant in real repositories

Counted categories include `unsupported` (every `obj.method()` call, every decorated definition, every conditional import),
`splatted_call` and `unknown_resolution:third-party`. The last one includes **stdlib** imports (`typing.Any`, `typing.cast`
show up as "third-party") although the analyzer is not meant to resolve them.

```
httpx, 3 open PR heads vs master:        coverage partial; unsupported 2175, unknown_resolution:third-party 1245,
                                         unknown_resolution:open-module 1074, splatted_call 17 (finding count 0)
itsdangerous dev case (2 branches):      partial; unsupported 205, unknown_resolution:third-party 243, splatted_call 8
```

T16 intends `partial` = "something *relevant to this analysis* was skipped" (PLAN: unparsable files, unknown resolutions,
skipped splatted calls, unsupported constructs). Counting every site in every file of every state makes `coverage` always
`partial` and the counts meaningless to a user ("1245 unresolved references" in a 3-PR check). Fix: report gaps only for
(a) files changed by any requested branch, (b) references that were actually evaluated (added references, target references
into changed modules), (c) modules consulted by culprit/resolution trials; classify stdlib/third-party imports as informational,
not as a gap. Keep the whole-repo totals out of `coverage`.

### V4-03 major — valid UTF-8 containing U+FFFD is treated as non-UTF-8 (false negative, regression)

`git.read_file` decodes with `errors="replace"`; `_Analysis.parse/references`, `StateIndex._module` and `coverage._sites` then test
`'�' in source` as the "non-UTF-8" detector. A perfectly valid UTF-8 file that contains the replacement character (charset
tests, unicode helpers, user-facing strings) is therefore skipped.

```
base: app/m.py (def f, def g)       A: removes f
B: app/use.py = from app.m import f / S = "<U+FFFD> literal replacement char" / f(1)     (valid UTF-8)
crosswire (0.3.1) check A B                       -> CW001 [B × A] `app.m.f` … removed in A         exit 1
crosswire (0.4.0) check A B                       -> No semantic conflicts … Limitation: non_utf8: app/use.py:1     exit 0
crosswire (0.4.0) check --target main --combined A B   -> same miss
```

Fix: decide validity by decoding strictly (`bytes.decode('utf-8')` raising) — or honour the PEP 263 coding cookie — in `read_file`
and return a `SkippedBlob('non-utf8')`; never infer it from the replacement character.

### V4-04 major — V3-03 only partially fixed (`open_module`)

R1 asks that a module with a star import, `__getattr__`, or `globals()`/`sys.modules[__name__]` mutation be *open*. `open_module`
recognises a literal `def __getattr__`, star imports, `globals()` and `sys.modules[__name__]` subscripts. These common lazy-export
forms are not recognised, so a removed name is reported as CW001 (all produce a false positive in pairwise **and** combined):

```
A replaces `def f` in app/m.py with …                                    B adds `from app.m import f; f(1)`
  from app._lazy import __getattr__                                       -> CW001 (FP)
  __getattr__ = __import__("app._lazy").__getattr__                      -> CW001 (FP)
  import lazy_loader as lazy
  __getattr__, __dir__, __all__ = lazy.attach(__name__, submod_attrs=…)  -> CW001 (FP)   (pattern used by scipy/scikit-image)
  locals().update(vars(__import__("app.impl")))   |   exec("from app.impl import *")   -> CW001 (FP)
```

Only `sys.modules[__name__].__dict__.update(...)` is caught. Fix: treat as open any module-level binding of the name `__getattr__`
(def, import, assignment target incl. tuples), and any module-level call to `exec`, `eval`, `locals`, `vars`, `setattr` on the module,
`importlib`/`__import__` that feeds a namespace update; add the cases above as regression tests.

### V4-05 minor — `limitations` per finding is dead

The field exists in schemas, JSON, SARIF and text, but nothing sets it. A finding with `culprits_exact: false`, `location: "branch"`
or an unresolved intermediate hop gives the consumer no per-finding caveat; the brief says "every finding has `limitations` (list)"
which holds only trivially. Populate (e.g. "culprit set not minimal: > 3 candidates", "location from branch tip").

### V4-06 minor — combined/plan lose rename evidence

README demo: pairwise `Hint: use billing.create_charge`; `--combined`/`plan` for the same finding say
`restore or re-export billing.charge`. The rename evidence (`rename_hint` of the ApiChange) exists but is not carried into the state check.
Hints are still evidence-based (no unjustified hint found), just weaker where the evidence is available.

### V4-07 minor — repro assumptions

`reproduction()` emits `crosswire check --target T --combined <culprits> <owner>` with `shlex.join` (verified safe against branch
names such as `rm;touch${IFS}/tmp/PWNED`, `use$(touch${IFS}/tmp/PWNED2)`, `q'uote`: executed through `sh -c`, nothing ran).
It omits `--repo`, and always integrates the owner last, which can differ from the original order when owner and a culprit
conflict textually. Add `--repo <path>` when it was given, and keep user order.

## Checked and found correct

- **Exit codes / streams:** unknown ref → exit 2, empty stdout; unexpected exception → `crosswire: error: internal error: …` exit 2;

  worktree file and all non-object `.git` files byte-identical.
- **Determinism:** no-cache == cold cache == warm cache byte-identical JSON for pairwise, combined, plan; permuting branch order keeps the finding set;
  Python 3.12 smoke run OK.
- **T14 hints:** `pass \`x=\`` only for keyword-capable parameters (kw-only and pos-or-keyword yes; positional-only and "too many positional" → null);
  Django renumbering computed on the merged directory (skips 0003 taken by a third branch); `merge B first` only with `resolved_by`; CW005 `rebase X onto <culprits>`.
- **T15 repro:** exact for CW006 (`A B C`), target-caused (`feat-use` only), CW005 skip (`b1`), target-owned references (`rm`); null when culprits are inexact or
  `resolved_by` is set; shell-safe (see V4-07).
- **T17 schemas:** `report-v1`, `report-v2`, `plan-v2` are valid Draft 2020-12 and **validate real output** for 10 scenarios × {pairwise, combined, plan}
  (30/30; versions const 1/2, additive keys optional-with-default); all three ship in wheel **and** sdist (`uv build --offline`); `crosswire schema` prints the
  packaged file offline.
- **T18 robustness:** shallow clone → `shallow repository: fetch full history before analysis` exit 2; unborn/empty repo → `unborn or empty repository` exit 2;
  bare repository works (also with a dangling `HEAD`); a submodule is reported (`submodule: 1 site(s)`), not initialised; real non-UTF-8 (latin-1) files are
  reported and skipped; a 3.6 MB `.py` is `oversize`, not read, no crash, analysis continues. (Exception: U+FFFD, V4-03.)
- **Conservative principle:** third-party/`unknown` never reported; star-import/`__getattr__`/`globals()` modules open (modulo V4-04); `from pkg import sub` resolves to
  the submodule; module→package conversions not reported as removals.

## Verdict

The direction is right: one core, adapters, two releases, a byte-identical gate before any feature.
But the protocol as drafted would not let Python move out of the core without either leaving Python logic
behind or changing behaviour, and several Go-contract statements are wrong against the real compiler.

## 1. Is the `LanguageAdapter` protocol sufficient and minimal?

### What the code actually depends on

I traced every Python-specific dependency in the core. The draft protocol covers the small ones and
misses the structural ones.

**Missing: the verdict carries more than a status.** `combined.py` and `coverage.py` use the full
`Resolution(status, symbol, files, reason)`:

- `files` (consulted paths) drives culprit-candidate selection: `relevant = set(tip.files) | set(final.files)`,
  then `candidates = [other … if _changed_paths(summaries[other]) & relevant]`. Without consulted files
  there is no culprit search, no `resolved_by`, and no coverage scope.
- `symbol` (with parameters) is required by `_broken` to run the call check against both the tip and the
  integrated resolution, and by `keyword_hint`.
- `reason` subtypes (`third-party`, `stdlib`, `skipped-blob`, `open-module`, `parse-failure`) are used by
  `_broken` and by `coverage.inspect` to decide what is a gap and what is out of scope.

`Verdict = valid | broken(reason) | unknown(reason)` loses the first two. Make `resolve` return
`Resolution(verdict, symbol: Symbol | None, files: tuple[str, ...], reason: Reason)` with `Reason` a closed
core enum (`external`, `skipped-blob`, `parse-failure`, `open-namespace`, `unsupported-construct`,
`depth-limit`, …) plus free text. `external` replaces the Python-specific `stdlib`/`third-party` split.

**Missing: the per-branch summarisation step.** `engine._Analysis.side` (about 100 lines) is the largest
block of Python semantics and has no protocol entry. It does the following:

- maps changed files to modules and handles `R` renames, so a renamed file is a removed module plus a replacement lookup;
- computes `redefined` from AST dumps and `definitions` for CW003;
- computes `migrations`, with `cw004._DJANGO` hard-coded, and applies `is_open` to filter removals.

If this stays in the core, Go cannot plug in (a Go file rename inside a package changes nothing, a directory
move is a package move). If it moves into the adapter without being in the protocol, Altair will invent an
interface during T21. Add:
`summarize(base: Snapshot, tip: Snapshot, changes: Sequence[FileChange], ctx) -> AdapterSummary`, where
`AdapterSummary` is opaque, JSON-serialisable and carries adapter name and version. The core stores it in the
cache and hands it back to `rules()`.
The core keeps only generic derived sets (`touched`, `referenced`) for the `interacts()` pre-filter.

**Missing: rule-specific data and plan-level hooks.** `planner.py:36` re-scans `.py` files for migration
collisions, `diagnostics.migration_hint` re-parses Django paths, and `engine` special-cases `cw004`.
`rules()` returning `Rule` objects is not enough because those rules also need the `AdapterSummary` extras
and a plan-state hook. Define `Rule.check_pair(ctx)` and `Rule.check_state(snapshot, changed)` (see M4).

**Missing: ownership of text.** Golden byte-identity needs messages, hints and symbol rendering to come
from the adapter (`"`billing.charge` is used here but was removed in X (renamed to `billing.create_charge`?)"`,
`pass `name=``, `positional-only argument passed as keyword`). Add `render(finding_kind, symbol, ctx) -> str`
and `hint(...)`. Otherwise Python wording stays in the core and Go output reads as Python.

**Smaller, but they will bite in T21:**

- `Snapshot` and `Source` are undefined. The git read layer (2 MB blob limit, strict UTF-8, `SkippedBlob`) is
  core. Consulted-file tracking is currently done by hand in `StateIndex`; make `Snapshot.read()` record it
  automatically so an adapter cannot forget it.
- `Use` equality: the core dedupes with `(path, module, name, call)` keys, line-tolerant `Counter` matching in
  `added_references`, and `_location` re-finds a site by shape equality after integration. The "opaque call
  shape" must therefore be hashable, comparable and JSON-serialisable. Specify that.
- `ApiChange.kind` is a closed `removed | signature_changed`, and `rename_hint` is computed in `diffing` by
  comparing a Python-shaped `shape` string. Both must be adapter-owned and extensible; the core needs only the
  two categories that map to CW001 and CW002.
- Exceptions: "adapters never raise" must be enforced, not trusted. Wrap every adapter call in the core and
  convert an exception into `unknown(internal-error)` plus a coverage gap, so an adapter bug can never
  become a conflict (the conservative principle).

### What breaks when the third language arrives (M1)

Python and Go both have "one name, one symbol, one signature". The next languages do not.

1. **Overload sets (Java, TS, PHP not).** `check_call(use, old: Symbol, new: Symbol)` takes single symbols.
   A Java removal of one overload, or an added overload that makes a call ambiguous, needs `SymbolGroup`.
   Identity must carry a discriminator (`qualname + signature`), and `ApiChange` must report group deltas.
2. **File→namespace multiplicity.** The draft's `module_of(path) -> str | None` returns one module per file.
   Go and Java put many files in one namespace; PHP and TS can put several namespaces in one file. The core
   uses "module" for API grouping, `touched_modules`, `definitions[module]` and CW003. Rename it
   `namespaces_of(path, ctx) -> tuple[str, ...]` and define CW003 over a namespace, not a file.
3. **Declaration merging.** TS interface and namespace merging, Go packages and Java partial classes make
   "two definitions of one name" legitimate in some kinds and an error in others. Duplicates need a per-kind
   policy supplied by the adapter, not a global CW003 rule.
4. **Identity normalisation.** PHP names are case-insensitive for functions and classes; TS has separate
   type and value namespaces. Add `normalize(name, kind)`.
5. **Hard-coded member skipping.** CW001/CW002 contain `'.' in change.qualname` (skip methods). For Go
   methods, Java methods and TS members this is exactly the common case. Make it adapter policy:
   `Use.target.kind` and an `is_resolvable(kind)` capability.
6. **Roots and options.** `--src` is a Python concept threaded through `AnalysisRun`, the cache key
   `(tip, base, roots)`, `diagnostics.reproduction` and the planner. Polyglot needs per-language context in
   the cache key and either `--src python:src` or per-language config; decide the CLI and `repro` format now,
   because `repro` is part of the stable JSON.
7. **Output identity.** `symbol` strings are not unique across languages (`billing.charge`,
   `billing.Charge`). Add an optional `language` to findings and coverage categories. Decide before T21
   whether it is emitted for Python-only runs (breaks byte-identity; I recommend "only when a non-Python
   adapter contributed a finding or a limitation").

### Is it minimal?

The draft is minimal in the wrong places: `claims`, `context`, `module_of` and `version` are cheap, while
the three things that cost the most (summarisation, the resolution record, text) are absent. After the
additions above the surface is about 12 methods. I would not trim anything else; `rules()` and
`check_state()` carry what is specific to a language.

### Direct answers

- **Minimal for Python and Go?** Not yet; B1.
- **Third language?** Overloads, namespace multiplicity, declaration merging, normalisation and member
  policy will break it; M1 lists them.

## 2. Can T21 be proven byte-identical?

Yes, but "every golden, every v0.4 fixture and the 16 review scenarios" is a sample, and the plan's
premise needs correcting.

### Premise check

The plan says one `check_call` removes drift between pairwise and combined. In the code the binding logic is
already shared: `combined.py` calls `cw002.binding_error` at five sites. The duplicated logic is the
orchestration: pairwise compares the base signature (`change.old`) with the cause's tip signature, while
combined compares the use's own tip resolution with the integrated resolution. Those are different questions
on purpose. Unifying them into one function that takes `(call, old, new)` is fine, but the callers must keep
passing what they pass today, or outputs change. T21 should state this, otherwise a "cleanup" will alter
behaviour.

### Where byte-identity can break

- Cache: the cache schema and adapter version change the key; a 0.4.0 cache directory must be ignored
  cleanly, and a cache written by 0.5 must not be read by 0.4.0 (a downgrade). Test cross-version cache reuse.
- stderr: parse warnings are printed once per `(path, blob)` and ordered by evaluation order; any
  reordering of evaluation changes stderr bytes.
- Dict and set iteration order inside `limitations`, `limits`, `skipped`, `repro`.
- `language-extra-missing` (M2), a `language` field (M1.7) and `limits.trials` (T23) are additive changes;
  they must land after the gate, as planned, and the plan must say that M2 and M1.7 are excluded from 0.5a.
- `--version` output changes by design; list it as the one excluded byte.

### Independent check I would run

1. **Reference artifact.** The `crosswire==0.4.0` wheel from PyPI (hash pinned), in its own venv. Not the
   worktree, not a rebuilt 0.4.0.
2. **Differential runner.** For each repository state: run both implementations over
   {pairwise, `--combined`, `plan`} × {text, json, github, sarif} × {`--no-cache`, cold cache, warm cache,
   a cache written by the other version} × `--src` variants × input-order permutations of the branch list.
   Compare stdout, stderr, exit code and (for the cold cache) the set of files written. Byte-for-byte; no
   normalisation except the version string.
3. **Corpus, three layers.**
   - the repository's goldens and test fixtures (the current guard);
   - the 228 development cases, the 59 live PR pairs, the httpx and Django clones, and my 9,051-file/16-branch
     fixture;
   - a seeded generator of random small repositories over the constructs that exercise `python_analyzer`,
     `state` and `coverage`: package `__init__` re-exports, relative imports, star imports, lazy exports
     (`__getattr__`, `lazy.attach`), decorated and `TYPE_CHECKING` code, conditional definitions, renames,
     directory moves, invalid UTF-8, files above 2 MB, syntax errors, submodules, shallow clones, odd git
     states. A few thousand cases are enough.
4. **Unexercised-line check.** Run the differential corpus under `coverage.py` against the 0.4.0 code. Any
   line the corpus never executes is "unproven" and goes in a list for T21 to add a case for. This answers
   "is the sample large enough" with a number.
5. **Exhaustive small grid for `check_call`.** All combinations of up to three parameters (kinds ×
   defaults) against call shapes (positional count, keywords, star flags) through the old `binding_error` and
   the new `check_call`. This is cheap and covers the one function Altair is explicitly rewriting.
6. **Two independent runs.** Deneb and I each run the harness from our own builds, and compare result hashes.

I already have scenario repositories and a diff driver from the V4 and R3 reviews. I can turn them into a
committed differential harness under `docs/reviews/` if Polaris wants it for T21.

## 3. The Go contract

All results below are from go1.27.1 in scratch modules (`go build ./...`, `go vet ./...`).

### Empirical check of the supported types

| Contract claim | Observed | Verdict |
| --- | --- | --- |
| GO-1: removed exported name, oracle `undefined: pkg.Name` | `bar/b.go:5:29: undefined: foo.Old` | correct |
| GO-2: removed package, oracle "package … is not in std" / no module provides | online: `cannot find module providing package … reading https://example.com/m/foo?go-get=1: 404`; with `GOPROXY=off`: `cannot find module providing package … module lookup disabled by GOPROXY=off`. "is not in std" appears only for dotless paths | **string wrong**; needs pinned env (M6) |
| GO-3: arity change, oracle `not enough / too many arguments` | `too many arguments in call to foo.Old`, correct for fixed arity | correct for fixed arity |
| GO-3: "variadic added/removed" | `Old(a, b int)` → `Old(a int, b ...int)`: the old call `foo.Old(1, 2)` **compiles** | **wrong** for "added" (M7) |
| GO-4: same name, different files, `X redeclared in this block` | confirmed; methods: `method T.M already declared at …`; imports: `strings redeclared in this block` | correct, but message set is larger |
| GO-4 in `_test.go` files | `go build ./...` passes; only `go vet ./...` reports `helper redeclared in this block` | contract excludes tests; oracle sees them via vet |
| GO-5 / build tags | `os_linux.go` + `os_other.go` (`!linux`) each define `OS()`: compiles; adding a third file with `//go:build linux` redeclares only under `GOOS=linux`, not on darwin | result depends on host configuration (M5, M6) |
| Package = directory | a directory `foo` with `package other` compiles and is used as `other.F()` | uses go by package clause, not directory (m2) |
| Dependent errors | `foo` has a redeclaration and `bar` uses `foo.Missing`: only the `foo` error is reported | dependent errors are masked (M6) |

### Is GO-4 the most valuable rule?

It is the right first one, but not clearly the only top one.

For GO-4: it is compile-certain, the oracle needs no interpretation, it works from the two tips alone,
and it covers a very common situation (two PRs each extract or add a helper with the same name). Unlike
CW001/CW002 it needs no resolution, so it has few false-positive paths and a low unknown rate.
Two other rules that the draft lacks are comparable: unused or missing imports per file (M8a), and import
cycles (M8b). I have no frequency data for any of them. Before the contract is frozen, S19 should run a
**category census**: replay merge commits of 3–5 public Go repositories and classify the compiler errors of
"clean merge, broken build" outcomes and of the follow-up fix commits. Rank the rules by observed counts,
not by intuition (mine included).

### M5: required fixes to GO-4

1. **False positives with build constraints.** The draft says guarded definitions "count as defined".
   GO-4 flags the same identifier in two files, and two files with mutually exclusive constraints
   (`foo_linux.go` and `foo_other.go`, or `//go:build linux` vs `!linux`) legitimately define the same name.
   Filename suffixes (`_linux.go`, `_amd64.go`, `_test.go`) are implicit constraints; the contract mentions
   only `//go:build`. Rule: flag only when both definitions are unconditionally active or when both
   constraint sets are satisfiable together under the oracle configuration; otherwise `unknown`
   ("constraint-dependent") with a gap.
2. **State-based, not summary-based.** In the Python code CW003 compares AST dumps and skips identical
   definitions, because identical additions in a Python module would merge as one. In Go, identical
   definitions in two files **still fail to compile**. The "both branches added a helper" case, which is the
   most common instance, is exactly the identical-text case. GO-4 must therefore not reuse the CW003
   equality filter.
3. **Same file, any hunk.** The draft says "different files". Two additions to one file at different
   positions merge cleanly and also redeclare. Define the rule as "same package namespace, any file,
   textually clean merge".
4. **Symbol kinds.** Cover methods (`T.M`), types, vars, consts, funcs, and per-file import names; `init`
   and `_` are exempt.
5. **Test files.** Define two namespaces per directory: package files, and package files plus same-package
   `_test.go` files; external `foo_test` is a third. Two PRs adding `newTestServer` in different test files
   are a likely common case. They are only visible through `go vet`, which the contract's oracle already
   runs.
6. **Severity.** CW003 is a warning in Python and an error in Go. `combined.py` hard-codes
   `'warning'` for resolved pairs and passes through `f.severity` for CW003 pairs; check that exit codes and
   JSON severities are consistent for polyglot runs, and document that the same rule id has per-language
   severity.

### M4: a state-invariant primitive

CW001/CW002 are implemented as "reference added by B × API removed or changed by A" and, in combined mode,
as "was valid at the tip, broken in the integrated state". Go's compile failures are mostly state
invariants: no redeclaration in a package, every used import is bound and every bound import is used, the
import graph is acyclic, every exported reference resolves. They hold or fail on a *state*, and culprit
attribution is exactly the trial loop that `combined.py` already contains. The protocol should expose that:

`violations(snapshot, scope) -> list[Violation]`, evaluated by the core on the target, each tip, the
integrated state and trial subsets. A violation present in the integrated state and absent from the target
and from every proper subset has exact culprits. Python's CW001/CW002/CW006 are a special case. This also
removes the need for Go to imitate Python's pairwise summaries.

### Oracle checkability and hermeticity (M6)

GO-1 and GO-3 (fixed arity) are oracle-checkable as written. The oracle needs to be specified more tightly
than "pinned `go build ./... && go vet ./...`":

- `GOTOOLCHAIN=local` with the toolchain binary hash pinned (error wording differs between releases), and the
  case matching by position and category rather than text.
- `GOPROXY=off`, `GOFLAGS=-mod=readonly`, `GOFLAGS` and `GOCACHE` fixed, and a policy for dependency
  download (a repository whose modules are not vendored or cached is an environment failure, hence
  unlabelled, never a negative control).
- `GOOS`/`GOARCH`/tags fixed per case, recorded in the manifest. A redeclaration can exist only under one
  configuration (shown above).
- `-gcflags=-e` (the compiler stops after ten errors per package by default).
- Masking: a package that fails to compile prevents its dependents from being checked, so a case with two
  root causes in dependent packages undercounts the recall denominator, and attribution trials may be
  hidden. Either build with `-gcflags=-e` plus `go vet` per package, or restrict cases to one root cause and
  say so.
- GO-2 evidence: use `cannot find module providing package` / `no required module provides package` and the
  import path; drop "is not in std".
- Vet findings: keep the "classified separately" rule, and compile-category vet errors (redeclaration in test
  files) must be separated from style findings by category, not by text.

### The supported-type statements (M7)

- **GO-3:** adding a variadic parameter to the end does not break existing calls. Define the check as:
  broken iff the new signature cannot accept `n` arguments (`n < required`, or `n > max` and not
  variadic); removing a variadic parameter can break. A call `f(g())` spreading a multi-value result has
  unknown arity, so it is `unknown`.
- **Result-count changes** (`a, b := G()` after `G` stops returning an error) fail with `assignment mismatch:
  2 variables but G returns 1 value`. This is common and appears in neither the supported nor the unsupported
  list. Either add it (CW002, evidence `assignment mismatch`) for call sites whose assignment shape is
  syntactic, or list it as a gap.

### M8: missing compile-certain, syntactic rules

All three were verified with the compiler.

a. **Per-file imports after a clean merge.**
   - A removes one of two uses of `strings`, B removes the other; the import line is untouched, so the merge is
     clean and fails with `"strings" imported and not used`.
   - A removes the only use and the import; B adds a use in a hunk elsewhere; the merge fails with
     `undefined: strings`.
   - Both add the same import line: `strings redeclared in this block`.

   Go's import binding is per file, so this is a file-local check needing no type information: compare the
   import set with the set of `ident.` selector uses of each import name, and report `unknown` if the name is
   shadowed anywhere in the file. In my judgement this is a top-three Go merge failure.
b. **Import cycles.** A makes `foo` import `bar`, B makes `bar` import `foo`: `import cycle not allowed`.
   The check is a graph cycle over package import paths in the integrated state; no types, trivial label.
c. **Same-package unqualified references.** The model says unexported identifiers matter within a package,
   yet GO-1 covers only `pkg.Name`. A removes the unexported `helper` (and its uses) from `a.go`; B adds
   `helper()` in `b.go`: `undefined: helper`. This is probably more frequent than cross-package removal.
   Conservative implementation: bare call identifiers with no local binding of that name in the enclosing
   function.

### Is the unsupported list honest?

Yes in what it lists: types, method calls, interfaces, struct fields, generics, embedding, cgo, linkname,
dot-imports, build-tag generated code, vendoring. Items to add: result-count changes (above), function
values and multi-value forwarding, method expressions, `internal/` visibility violations, `//go:embed`,
import aliases that cannot be resolved, nested modules and `go.work` (it mentions `replace` and `go.work`
only under imports).

### Smaller Go points

- **m1:** tree-sitter recovers from syntax errors and returns a tree with `ERROR`/`MISSING` nodes; it does
  not raise. Without a rule, a broken file silently yields partial symbols. Treat any ERROR/MISSING node in a
  file as a parse failure (gap, `unknown`), mirroring the Python behaviour, and pin the grammar (new syntax:
  range-over-func, generic aliases).
- **m2:** package identifiers in `pkg.Name` are the *package clause name*, which can differ from the directory
  (verified); the import alias or the target's package clause must be read. Multiple `go.mod` files and
  `go.work` make "module path from go.mod" a per-file lookup (nearest `go.mod` wins). `foo_test` external
  packages are separate. `/vN` major-version directories.
- **m3:** if every `x.M()` and `x.Field` counts as a coverage gap, any non-trivial Go PR is permanently
  `partial`; this is the same mistake as the early v0.4 "constant partial". Scope gaps to selectors whose
  member name equals a name removed or changed by another branch (cheap, name-based), and state it in the
  contract.
- **m4:** GO-5 (conjunctive build-tag removal) needs a multi-configuration oracle and is rare. Defer it;
  GO-4's constraint handling already needs most of the machinery.

## 4. Holdout plan for 0.5a and Amendment M3

### M9: the gate cannot pass as specified

The sealed v2 holdout has 20 positives per rule (CW001, CW002, CW006) and 180 controls. QUALITY Q1.7
requires point estimate ≥ 95 % **and** lower 95 % Wilson bound ≥ 90 %. With 20 predictions and zero false
positives the Wilson lower bound is 83.89 %. A zero-FP lower bound of 90 % needs about 35 predictions
(`n ≥ 9 z²`). So each per-rule precision cell **structurally cannot pass**, whatever the detector does. The
micro-average over 60 predictions (lower bound 93.98 % at zero FP) can. And clustered intervals are not
estimable with four repositories.

Before S18 the plan must declare:

1. Whether the gate applies per rule or to the micro-average, and what each cell is allowed to report
   ("insufficient", "cannot pass by design", "pass").
2. The primary metric, the interval method and the counting unit, written down before the run (a
   pre-registration; the document is committed, and its hash is added to the seal log).
3. **The failure path.** If the holdout fails or is inconclusive, the detector must not be tuned against it.
   State that a replacement holdout (v3) is sealed before any fix is made. Without this, the first failing
   number will create pressure to "fix" and re-measure.

### Leakage and independence risks

- **Generator independence.** From the public decisions log, the v2 holdout was built with the same case
  generator family as the development scaffolds (probe wrappers, `r5`/`r6` families). If so, it generalises
  across repositories but not across mechanisms; the report must say that, and the plan should not call
  100 % on it "generalisation". (Q1.5 reserved whole mutation families for the holdout; I could not check
  this without reading content, and I have not.)
- **Repository overlap between S17 and the holdout.** S17 adds development repositories and mined history
  while the holdout stays sealed. Deneb owns both lists, so nothing prevents an accidental overlap. Proposal:
  Deneb publishes salted hashes of the S17 repository identifiers and commit ranges; the holdout owner
  checks set intersection without revealing identities. If I am to audit this, give me explicit
  authorisation to run the intersection and record only the count.
- **Same OS user (E4-02).** S18 is the first time anyone runs a detector against the holdout. The measurement
  should run as a separate OS user or from a read-only ephemeral copy, with the seal verified before and
  after. The agents that implemented 0.5a must not have run anything against `~/.crosswire-holdout`.
- **Source freeze order.** The measured source must be byte-identical to the one that ships; list the freeze
  hash in the report and re-verify after any CI-driven edit.
- **Detector changes after v0.4.** T21 is a refactor, so the 0.5a measurement is in effect a second
  measurement of the 0.4.0 behaviour. Any behaviour change between the freeze and S18 (including bug fixes
  motivated by S17 results) must be listed; those motivated by development data are allowed, those
  motivated by holdout-adjacent artefacts are not.
- **Single shot.** The `run_holdout` marker enforces one attempt; keep the marker outside the working tree
  and include it in the audit.

### M10: Amendment M3 is under-specified

"No new diagnostics relative to the target" is the right direction (it rescues hyperframe and itsdangerous,
48 cases and two repositories, making five repositories and clustered intervals estimable). It needs the
identity function before any number is produced:

- Diagnostics are compared as a multiset keyed by `(file, rule, normalised message with symbol)`; **not by
  line**, because the branches move lines. Say how two diagnostics with identical keys are counted.
- Pre-existing errors can change inference (an `Unknown` type suppresses or creates later errors). Attribution
  trials must apply the same differential rule to every subset state, with the target set as the baseline.

## 3. The two combined/plan false negatives: detector, not label

Cases `06e9c19f…` (pytest-repeat, `pytest_repeat.TestCase`) and `4f2f5550…` (trove-classifiers, `trove_classifiers.Dict`).

**Label.** Correct: pyright reproduces `reportMissingImports` for the consumer in the integrated state and none in either tip or the target; the break is real (the consumer imports a module that branch A moved away).

**Reproduction** (I rebuilt both repositories from the archive and ran the detector source of `94a7417`, pairwise / `--combined` / `plan`, cache off): pairwise reports CW001 `pytest_repeat.TestCase` (exit 1); combined and plan report **zero findings, exit 0, coverage `partial`**. Variants on the same repository: the consumer written as `from pytest_repeat import TestCase` behaves the same; a consumer using a name *defined* in the module (`api.pytest_addoption`) is found by all three modes. This is exactly the split between the 3 matched and the 2 missed combined cases: `sniffio.AsyncLibraryNotFoundError`, `certifi.__main__.args`, `iniconfig.COMMENTCHARS` are defined in their module; `TestCase` (`from unittest import TestCase`) and `Dict` (`from typing import Dict`) are imported names re-exported through it.

**Root cause (instrumented copy of `combined.py`).** In `analyze_combined`, each branch's uses are processed as `tip = tip_index.resolve_use(ref); if tip.status != 'valid': continue`. For a re-exported import the Python index reports origin `stdlib`/`third-party`, which the adapter maps to `Resolution('unknown', …, Reason.EXTERNAL)`; I observed `tip B pytest_repeat TestCase unknown` and `trove_classifiers Dict unknown`. The use is therefore dropped before the final state is ever examined, although the whole module is gone in the integrated state. Pairwise has no such gate for module removal, hence the disagreement. The `partial` coverage does not name the site, so a user sees a clean exit.

**Why this is a detector issue and not a contract gap.** M2 and the label ask only whether the use file breaks because the module is missing; no symbol identity is required, so "the name is an external re-export" does not make the break unsupported. A defensible fix: when the use's module path exists at the tip but not in the integrated state, report CW001 regardless of the name's origin (or at least record a limitation naming the use). That is a behaviour change for Altair, with the two cases as regressions (pairwise/combined/plan equality on this shape). The measurement task rightly makes no fix.

## Verdict

**The refactor is acceptable as the T21 checkpoint (behaviour is proven byte-identical, see `v0.5-t21-vega.md`) but the adapter layer is not yet Go-ready.**
Nothing here is a regression and nothing blocks accepting T21. There are **0 blocking** and **4 major** findings, all of which must be fixed before the first Go
code (0.5b) because each makes a second adapter either crash or silently lose its cache, plus 4 moderate and several minor findings. The good news: they are
all cheap to fix *now*, while Python is the only adapter, and each can be fixed without changing a byte of Python output (my replay harness is reusable as the gate).

| ID | Severity | Topic |
|---|---|---|
| M1 | major | Ten adapter members the core calls are not in the `LanguageAdapter` protocol |
| M2 | major | Core still assumes the first adapter's Python-shaped `legacy` summary (`engine.side`, `cache.get`): a second adapter crashes or kills the cache |
| M3 | major | `violations()` is computed and discarded; no consumer, no culprit logic, no test (P2 primitive is scaffolding only) |
| M4 | major | Cache layer: swallowed adapter errors, asymmetric exception handling, repeated context computation, manual adapter version |
| L1 | moderate | Python assumptions still hard-coded in the core (defaults, `[0]` namespace, `'undefined'` literal, direct imports of Python modules) |
| L2 | moderate | Finding → adapter routing for hints is first-match across adapters; `Finding` has no language/owner; registry rebuilt per call |
| L3 | moderate | Protocol shape gaps Go will hit (single ctx for two snapshots, tip-only ctx in `summarize`, path-only `namespaces_of`, per-first-declaration duplicate policy) |
| L4 | moderate | No second-adapter conformance test |
| m1–m6 | minor | docstring vs imports, duplicate `Resolution` name, unused fields, shim inventory, `Snapshot.roots` semantics, others |

## M1 — protocol incomplete: the core calls members the protocol does not declare (major)

I extracted every attribute the core reads from an adapter object and diffed it against the members of `LanguageAdapter`. **Used by the core, absent from the protocol:**

| Member | Core call site |
|---|---|
| `cache_identity` | `engine._Analysis.index` (index cache key) |
| `index` | `engine._Analysis.index` (builds the resolution index) |
| `source_roots` | `engine.roots_for` (hard-wired to `adapters['python']`) |
| `parse`, `references` | `engine._Analysis.parse/references`, `combined.target_candidates`, `combined` target recheck |
| `parse_failures` | `engine._Analysis.parse_failures` (gate for writing the cache) |
| `warn_parse` | `engine._Analysis.warn_parse`, `coverage.inspect` |
| `coverage_sites`, `coverage_reason`, `path_gaps` | `coverage.inspect` |

`runtime_checkable` only tests member presence, so `PythonAdapter` passes `isinstance(…, LanguageAdapter)` while a Go adapter written **to the protocol** would raise
`AttributeError` at the first `index()`/`coverage` call. P1 says adapter programming errors are operational errors (exit 2), so that is a crash, not a degraded result.
**Fix:** either add these to the protocol with neutral semantics (e.g. `cache_identity(ctx)`, a `resolver(snap, ctx, consulted)` factory replacing `index`, `coverage(src, ctx)`,
`parse_failures` as a counter on a `Stats` object, `warn(path, sha)`), or move each into the Python adapter's private surface and remove the core call. The `references` /
`parse` / `warn_parse` / `source_roots` calls in `_Analysis` are the Python-only core and belong to M2/L1.

## M2 — the core assumes the first adapter's `legacy` Python summary (major)

- `engine._Analysis.side` ends with `return replace(summaries[0].legacy, label=label, semantics=summaries)`; `cache.SummaryCache.get` ends with
  `summary = replace(semantics[0].legacy, semantics=semantics)`.
- `legacy` is the Python `BranchSummary`; it is the carrier of `label`, `tip`, `base`, `roots`, `changes` **and** the Python-shaped `api`, `references`,
  `definitions`, `migrations`, `touched_modules`, `referenced_modules` (`model.BranchSummary` still has all of them).
- Consequence with a second adapter: in `side()` the order is the registry's insertion order — fine only while `{'python': …}` is the only entry; add a Go adapter first and
  `replace(None, …)` raises `TypeError` (checked: `dataclasses.replace(None, a=1)` → `TypeError`), an internal error, exit 2. In `cache.get` the order comes from the JSON object
  (`sort_keys`, alphabetical), and `'go' < 'python'`, so `semantics[0].legacy` is `None` → the `TypeError` is swallowed by the `except (…, TypeError, …)` and **every lookup is a
  silent cache miss** — correct output, no cache, no signal. The `put` side then calls `encode(summary.legacy)` for Python only, so the cache still writes (see M4).
- **Fix before 0.5b:** make `BranchSummary` language-neutral (`label, tip, base, roots, changes, semantics`) and have the Python adapter keep its legacy fields inside its own
  `LanguageSummary`, with `cw001/002/003` reading `semantics` only; or, as an intermediate step, select the legacy carrier by `language == 'python'` instead of `[0]`. The
  intermediate step is a 2-line change per site and keeps T21 byte-identical.

## M3 — `violations()` is evaluated, cached and then ignored (major)

`engine._Analysis.violations` (called from `side()` for base and tip, and from `analyze_combined` for target, each tip, the integrated state, every trial and every textual-conflict
attempt) stores the adapter's result in `self.invariants`, and **no caller reads it**: `grep` shows every call site discards the return value; no rule or finding path consumes
`invariants`. The P2 text — "a violation present in the integrated state and absent from the target and every proper subset has exact culprits" — has no implementation: no
set difference, no subset search over violations, no `Finding` constructed from a `Violation` (note also `Violation.identity` is an untyped tuple and `Finding`/`CombinedFinding`
have no field to carry it). It is dead scaffolding today, which is acceptable for a byte-identity checkpoint, but:

1. Say so in the code (a `# no consumer until 0.5b` comment) and in `docs/`, so no reviewer or user reads the call sites as protection.
2. Cost: the calls sit inside the trial loops of `analyze_combined`; with a Go adapter doing a package-wide check each call is an expensive no-op until the consumer exists. The cache
   key is `(sha, cache_identity(ctx), paths)`: `paths` is the **changed-file union**, so a different union is a different evaluation; for a package-level invariant the adapter
   needs all files of the affected namespace, which `Scope(paths, context)` does not give it (it must recompute the namespace closure via `Snapshot.list()` and
   `namespaces_of`). Decide now whether `Scope` carries the affected namespaces.
3. Add the consumer's contract test (a stub adapter returning one violation present only in the integrated state, expecting exact culprits and a finding) with the first Go code, not after.

## M4 — cache layer (major)

1. **Adapter programming errors are swallowed on read, crash on write.** `get` catches `(OSError, ValueError, TypeError, KeyError, AttributeError, OverflowError)` around
   `decode_summary` and the re-encode comparison, so a bug in an adapter's `decode_summary`/`encode_summary` is a cache miss, contradicting P1 ("adapter programming errors stay
   operational errors"). `put` catches only `(OSError, ValueError, TypeError)`, so an `AttributeError`/`KeyError` from `encode_summary` (e.g. `encode(None)` for a summary with
   no legacy payload) escapes and aborts the run although the docstring promises "caching failures never block analysis". Make both sides agree: catch **only** I/O and JSON
   errors (`OSError`, `ValueError` from `json`, and a dedicated `CorruptEntry` raised by the codec for malformed data); let programming errors propagate.
2. **Context recomputation.** `_contexts()` calls `adapter.context(Snapshot(…))` for base and tip, and is called from `_path` (in both `get` and `put`), from `get`'s validity
   comparison and from `_encode`: about 3 × 2 context builds per lookup and per branch, bypassing the run-level memo `_Analysis.context`. Trivial for Python (a tuple of roots);
   for a Go context that has to read `go.mod`/`go.work` and the package clause of every file (P2 `namespaces_of(path, ctx)` takes only a path, so the context must carry a
   path → package map for the commit) this is a whole-tree scan several times per branch. Compute the fingerprints once per `(commit, roots)` and pass them in.
3. **Staleness guard is a manual string.** The key is `[schema 4, crosswire __version__, ADAPTER_API_VERSION, base, tip, [name, adapter.version, ctx fingerprints]]`. While the
   package version stays `0.4.0` during development, any change to Python extraction logic that forgets to bump `PythonAdapter.version = '1'` serves stale summaries from a
   developer's or CI cache. Add a test that hashes the adapter's analysis source files and fails if the hash changed without a version bump, or fold that hash into the key in dev builds.
4. **`Snapshot.roots` is Python's notion.** `roots_for` (Python heuristic or `--src`) is passed into `Snapshot(..., roots)` for **every** adapter and into the cache path, so a
   Go summary's key changes with a Python `--src` choice (harmless, wasteful), and a Go adapter that reads `snap.roots` would use Python's. P2 says `--src` stays a Python
   option: keep the field Python-private (`PythonContext.roots`) and let the cache key use only per-adapter fingerprints.
5. Correct and worth keeping: strict validity check by re-encoding the decoded summary and comparing with the file; adapter set equality; the API-version/adapter-version/context
   fingerprints in both disk and run-level index keys (`index` key = `(sha, adapter.cache_identity(ctx), track)`); per-language payloads; atomic writes.
6. Pre-existing and unchanged (noted for completeness): cache files are never garbage-collected (my replay: 0.4.0 → 1 file, candidate → 2 files in the same directory after cross-seeding)
   and `git` rename/diff configuration is not part of the key.

## L1 — Python assumptions still hard-coded in the core (moderate)

Expected after T21 and listed so the 0.5b work has a checklist. Each of these is `'python'`/Python-shaped and must go through an adapter or a per-language loop:

- `engine._Analysis`: `context/index/semantic/namespaces(..., language='python')` defaults; `roots_for`, `warn_parse`, `parse`, `references` call `adapters['python']`;
  `PairContext.definition_dump` uses `adapters['python']`; `side()` registers tracked state with `self.index(sha, roots)` (Python only).
- `combined.py`: `analysis.semantic(summary).uses` (Python only) drives the main loop and the pairwise-explanation loop; target recheck uses `analysis.namespaces(...)[0]` and
  `analysis.references`; `symbol = f'{ref.module}.{ref.name}'` (Python dotted names; a Go package path contains `/`); **`rule = 'CW001' if reason == 'undefined'`** compares a
  free-text detail where `Verdict.reason == Reason.ABSENT` exists — the string contract between `adapter.breakage` and the core should be the enum.
- `coverage.inspect`: `analysis.index(commit, source_roots)` is Python-only; it never iterates adapters. A Go file's gaps would not be collected.
- Imports of Python modules from core files: `coverage.py` (`lang.python.coverage._sites`), `rules/cw002.py` (`lang.python.calls`), `rules/cw004.py`, `diffing.py`, `state.py`,
  `python_analyzer.py` — the `lang/__init__.py` docstring ("the core never imports parser implementations directly") is not true yet (minor m1). They are compatibility shims, so
  this is the removal schedule: the shims may now go, because both equality gates passed; keep only what tests monkeypatch (`coverage._sites`, `engine._Analysis.references`).

## L2 — finding ownership and registry (moderate)

- `diagnostics.hint` and `migration_hint` return the **first** adapter's non-empty answer (`next((advice for adapter in adapters_for(…).values() if (advice := …)), None)`), without
  regard to which language produced the finding; `Finding`/`CombinedFinding` carry no `language`. P2 plans the field "only when a non-Python adapter contributed" — until then route
  by rule id via `adapter.rules()` (the protocol already has it) so a Python hint can never answer a Go finding, and make adapters return `None` for foreign rule ids.
- `adapters_for(repo)` builds new adapter instances on every call: once per `_Analysis`, again in `planner._migration_findings`, in `diagnostics.hint` (`adapters_for(None)`),
  in `migration_hint`, and in `SummaryCache` (shared with `_Analysis`, good). Adapters carry run caches (`cache`, `indexes`, `module_cache`), so each fresh instance starts cold;
  harmless for Python's stateless hint, wrong for a Go adapter with a per-run tree-sitter parse cache. Inject the run's adapter map instead of re-creating it.

## L3 — protocol shape gaps Go will hit (moderate)

1. `definitions_equal(before, old, after, new, ctx)` takes **one** context for two snapshots (`PairContext.definitions_equal` passes the left side's). Python tolerates it because roots
   only feed an identity; for Go the two sides can have different `go.mod`/build tags. Take `(ctx_before, ctx_after)`.
2. `summarize(base_snap, tip_snap, changes, ctx)` gets only the tip context although `side()` computes the base context just above it. Pass both, or document that the adapter
   recomputes via `context(base_snap)` and does so through the run memo.
3. `namespaces_of(path, ctx)` is path-only: fine for Python, but Go/Java derive the namespace from file *content* (package clause), so the context must hold a whole-tree map. Say that in
   the protocol docstring and put the map's size into the cost model (see M4.2).
4. `duplicate_policy(kind)` is called with `group.declarations[0].kind` only (`cw003`); a group with mixed declaration kinds (Go `var` plus `func`) is judged by its first member. Pass
   the group, or iterate declarations.
5. `Resolution.dependencies` and `Resolution.gaps` (P1: "context dependencies, gaps") are defined, populated by nobody and read by nobody; either wire them (coverage could use
   `gaps` instead of `coverage_sites`) or drop them until needed.

## L4 — no second-adapter conformance test (moderate)

`tests/` contains the new equality test but nothing that registers a second, trivial adapter (a stub that claims `.txt`, returns empty summaries) and runs the three modes plus the cache
round-trip. That single test would have caught M1 and M2 today, and it is the right gate for the "protocol is Go-ready" claim: **with the stub registered first and last,
`check`, `--combined`, `plan` and a warm cache must still produce the Python result.**

## Minor

- **m1** `lang/__init__.py` docstring says the core never imports parser implementations; see L1 for the actual list.
- **m2** Two classes named `Resolution` (`lang/base.Resolution` and `lang/python/state.Resolution`); the shim `state.py` re-exports the Python one. Rename the Python-internal one.
- **m3** `Reason` mixes resolution reasons (`external`, `skipped-blob`, …) with verdict reasons (`absent`, `incompatible-call`, `invalid-baseline`); acceptable, but give the enum a docstring
  naming which operation may return which.
- **m4** `PythonAdapter.fingerprint` is a `staticmethod` with `lru_cache` (maxsize 256) keyed on the context: fine; the protocol declares an instance method, keep one style.
- **m5** `PythonAdapter.cache` / `module_cache` / `indexes` grow without bound for the life of a run (unchanged from 0.4.0's `_Analysis.cache`, now per adapter); note for the large-repo benchmark.
- **m6** `interacts()` compares `(a.rule_data and b.rule_data)` by truthiness: a language whose `rule_data` is a non-empty container for every branch (e.g. a Go summary with a
  constant marker) would make every pair "interact" and defeat the pairwise prefilter. Make `rule_data` an explicit "has state-rule inputs" flag or a set of rule ids.

## What I checked and found correct

- **Byte identity**: confirmed by my independent replay (12,971 pairs, 0 differences); this review found no behavioural defect.
- **Immutable inputs**: `Snapshot` exposes only Git object reads; no adapter code reads the working tree.
- **Context fingerprints are present at every cache level**: disk key, validity check, run-level index key, `contexts` memo key (`sha, roots, API version, language, adapter version`).
- **Cache cannot return another version's data**: schema 3 → 4 and a changed key mean 0.4.0 and candidate files never collide; foreign and corrupted files (six corruption shapes) were
  rejected in my replay with unchanged output.
- **Per-language containers keyed by `SymbolId(NamespaceId(language, …))`** throughout summaries, `interacts()`, `cw001–cw003` (`ctx.analysis.adapters[data.language]`): the CW rules are already
  language-parameterised; only the combined orchestration is not (L1).
- **`SymbolGroup` / `Declaration` / `Reason`** carry what P2 asked (singleton for Python, guards, visibility, overload-ready discriminator); `check_call` honours the "valid on old side first"
  rule (`INVALID_BASELINE` → unknown).

# T21 independent equality replay — Vega (task v0.5-t21-vega)

**Verdict: PASS.** Candidate `d01d5e6` (local, unpushed) is byte-identical to the released
`crosswire==0.4.0` wheel on stdout, stderr and exit code in all 12,971 compared runs
(33,068 process executions): **0 mismatches**.

Scope of the claim: the pairwise / `--combined` / `plan` / `schema` CLI behaviour over the fixtures
below. It is not a proof for inputs outside them (see Limitations).

## Method

- **Independence.** My own builder, runner and comparator, written under `/tmp/vega-t21/`
  (`build.py`, `build_err.py`, `run.py`). I did not import or run `benchmarks/t21_*.py` or
  `docs/validation/t21-baseline/`. Nothing was written into the repo except this report.
- **Baseline:** `uv venv /tmp/vega-t21/base` + `uv pip install crosswire==0.4.0` from PyPI (Python 3.11.17).
- **Candidate:** `git worktree add /tmp/vega-t21/cand d01d5e6`, own venv from `uv sync --locked`
  (`/tmp/vega-t21/candenv`, Python 3.11.17; `crosswire` imports from `/tmp/vega-t21/cand/src`).
  The shared repo `.venv` was not used.
- **Per comparison:** the pristine fixture is copied (`cp -a`) to the same path
  (`/tmp/vega-t21/run/<fixture>/repo`) for each side, so paths embedded in output (repro lines,
  SARIF URIs) are identical. Same argv, cwd, env: `LC_ALL=C TZ=UTC`, fixed `HOME`,
  `GIT_CONFIG_GLOBAL/SYSTEM=/dev/null`, fixed `GIT_*` identity and dates, `NO_COLOR=1`,
  `PYTHONHASHSEED` cycled over {0, 1, 2, 4242} per fixture (same value on both sides).
- **Compared:** raw bytes of stdout, stderr and the exit code. No normalisation, no sorting.
  (`--version` prints `crosswire 0.4.0` on both; nothing needed excluding.)
- **Side checks per run:** SHA-256 digest of the whole repo tree (worktree, refs, index, objects)
  before and after, and equality of the after-digests between sides; listing of what the run
  left under `.git/crosswire`.
- **Cache states** (for the canonical commands; `nocache` and `cold` for the others):
  `--no-cache`, cold, warm (own side run twice), pre-seeded by the 0.4.0 wheel (cross-version:
  candidate reads a 0.4.0 cache), pre-seeded by the candidate (0.4.0 reads a candidate cache),
  malformed (0.4.0-seeded cache files corrupted six ways: garbage bytes, truncated, empty,
  wrong-schema JSON, JSON list, tampered fields).

## Harness validation

- **Canary:** pointing the "candidate" slot at a wrapper that rewrites `CW001` → `CW0O1` in stdout on
  one fixture produced 80 of 104 mismatches (every pair whose output contained that rule id), so a
  one-character difference is detected and recorded with the full bytes of both sides.
- **Three harness artifacts, found and fixed, then re-run clean** (none was a tool difference):
  1. linked-worktree fixture: the copied worktree's `.git` file pointed back at the pristine fixture, so a run
     wrote its cache there. Fixed with `git worktree repair` after each copy; fixture cleaned; re-run.
  2. bare-repo fixture: my tree digest did not skip `crosswire/` and `objects/` at the repo root. Fixed; re-run.
  3. detached-HEAD prep used `git checkout`, whose index timestamps differ by second between the two sides.
     Replaced by writing `HEAD` directly; re-run.
  After the fixes `x_worktree`, `x_bare` and `x_simple` re-ran with identical counts and 0 differences,
  no pair with a modified worktree, refs or index, and equal tree digests between sides.

## Observations (not defects)

1. **Cache file bytes differ by design.** The cache schema is 3 in 0.4.0 and 4 in the candidate, and the file
   name hash covers the schema; seeding with the other version leaves one more cache file (e.g. 0.4.0 → 1 file,
   candidate → 2 files), as expected from a key change. Cross-version reads fall back to recompute with
   identical output, and malformed / foreign cache files never change output (882 + 882 + 882 pairs). I did not
   compare cache file contents; I compared presence and counts of files written, which was equal in
   nocache (always none), cold and warm in every pair.
2. **Both versions write loose git objects** (integrated-state commits) into the repo even with `--no-cache`; the
   set of objects written is identical on both sides (tree digests equal). This is 0.4.0 behaviour carried over,
   not a T21 regression, but worth knowing next to the "read-only" wording in the docs.
3. The candidate reports `crosswire 0.4.0`, so `--version` could not differ. When the version bumps, only that
   line (and the cache file names that hash the version) will differ.

## Limitations

- 100 of the 300 random repos I generated were run (seeded sample), and only 20 of ~75 non-canonical commands for
  each; the scenario and exotic fixtures ran the full matrix.
- Small fixtures only: no httpx / Django clones, no 9k-file fixture, no live PR pairs, no development-corpus cases
  (the 59 PR pairs and 228 cases remain Deneb's coverage).
- One platform (macOS, Python 3.11.17, one git version), `LC_ALL=C` only; no Windows, no other Python versions.
- I did not run a `coverage.py` pass over the 0.4.0 code to list lines my fixtures never reach; the unexercised
  parts of 0.4.0 are therefore unknown to me.
- Behaviour that T21 intentionally changes (language-extra-missing, `language` field, `limits.trials`) is not
  exercised by these fixtures; they contain only Python.
- Equality of stdout/stderr/exit code is what was proven, not equality of internal data structures.

## Reproduce

```
uv venv /tmp/vega-t21/base && uv pip install --python /tmp/vega-t21/base crosswire==0.4.0
git worktree add /tmp/vega-t21/cand d01d5e6 && (cd /tmp/vega-t21/cand && UV_PROJECT_ENVIRONMENT=/tmp/vega-t21/candenv uv sync --locked)
python3 /tmp/vega-t21/build.py 300 && python3 /tmp/vega-t21/build_err.py && JOBS=6 python3 /tmp/vega-t21/run.py
```

Any mismatch would be stored verbatim in `/tmp/vega-t21/out/mismatch/<fixture>__<command>__<mode>/`
(`base.stdout`, `cand.stdout`, `*.stderr`, `*.rc`, `cmd.txt`); there are none.

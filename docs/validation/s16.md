Task `v0.5-s16`. **Full Python kit PASS: 16 cases, 80 independent oracle states, 48 installed-product mode checks; detector/checker/apparatus stable.** Evidence is [s16-python/summary.json](s16-python/summary.json), with pinned toolchain, installed detector and apparatus hashes in [provenance.json](s16-python/provenance.json). No product source, sealed apparatus or holdout was changed. No commit was performed.

Eight language-neutral templates declare 16 cases: rename, delete, move module, arity, conjunctive three-branch removal, repair by a third branch, wildcard-open namespace and dynamic-open namespace, with a control for each. Template data includes branch parents/edits, logical declarations/use IDs, per-mode verdicts, per-language contract IDs and the exact oracle-failing subsets. Python source and site/module maps belong to the renderer. Go has no renderer yet; conjunctive/open cases explicitly have no supported Go counterpart. PY-3 re-export-chain and PY-6 migration coverage are not claimed by this requested scenario set.

Every case is checked through an installed crosswire subprocess in pairwise, combined and plan modes. All target/tip/subset source states first pass the independent template-validation stage: Pyright **1.1.407 basic** with fixed full-file scope, plus focused runtime use probes. The kit records oracle verdicts beside rendered contents and refuses oracle/template disagreements as kit bugs, before product execution for that case. Expected verdicts are never generated from crosswire output. Independent package/interpreter/Node/checker-engine hashes, installed detector bytes and apparatus hashes are retained, with stability checks across the run.

| Scenario | Conflict/boundary: pairwise / combined / plan | Control |
| --- | --- | --- |
| Rename, delete, move module, required arity | broken / broken / broken | valid in all modes; arity control adds an optional parameter |
| Conjunctive removal | valid / broken / broken | valid in all modes, retaining the alternative definition |
| Third-branch repair | broken / valid with resolved warning / valid | valid in all modes, using an unrelated surviving binding |
| Wildcard/dynamic open exports | unknown / unknown / unknown; zero findings | oracle-compatible unrelated use, still unknown because changed open exports are in scope |

Open-boundary cases are oracle-valid coverage checks, not semantic positives. Each requires an explicit open-namespace limitation and no findings. Closed controls cannot use unknown coverage to conceal a supported miss. Findings must name the correct use occurrence and emitted rule; small combined cases require exact minimal culprit evidence. Repair warnings must name their repairing branch. Every accepted planner prefix is checked against independent oracle truth, and every branch must be placed or blocked. Textual conflicts, skipped integrations, crashes/timeouts, extra findings and unrelated identities fail the run.

The template's edit operations, expected verdicts and oracle truth were unchanged. That intermediate diagnostic run is retained locally outside the repository; final evidence is from the corrected apparatus.

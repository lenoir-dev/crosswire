# v0.4 Python pilot — final measurements pending

**Development data, optimistic, not a gate.** PLAN v0.4 R2 supersedes the earlier
pilot and its preliminary numbers. Those numbers used production-only oracle
scope and M1 matching and must not be presented as current R2 measurements.

The old exposed holdout is retired, untouched and never measured. The new private
v2 holdout is sealed and verified: four repositories, 20 oracle positives for each
of CW001/CW002/CW006 and 180 controls. Only `holdout.sha256` and the combined eval
hash are public. **No holdout measurement is permitted in v0.4.** Its first run is
the separately authorized v0.5 checkpoint. All agents share one OS user; isolation
is procedural (instructions and independent audit), not a technical OS barrier.

The public development corpus retains 228 attempted cases: 179 eligible cases,
44 positives, and 49 explicit oracle exclusions. Historical direct mutations of
upstream declarations and supplemental **upstream API oracle scaffolds** are
separate strata. The scaffolds wrap real upstream API objects; they are not
natural upstream incidents. All 132 supplemental cases passed the identical
production-and-tests checker; 27 ambiguous controls also passed focused runtime
export smoke checks. Upstream test execution is not claimed.

The apparatus now implements M2, preserves positives as FN on detector failures,
uses emitted-rule buckets, verifies repository/ref integrity, checks aggregate
keys and values, suppresses small cells, and pins Node/Python/checker artifacts
and Python distribution hashes. Repository-clustered intervals are not estimable
below five eligible repositories; future gate lower bounds use the stricter
Wilson/clustered bound when estimable.

PR snapshot noise, and the S14 matrix are waiting for Polaris's exact **src frozen**
message. The performance matrix includes the fixed Vega 9000-Python-file,
